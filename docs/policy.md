# BRICK 프로젝트 정책

## 현재 프로젝트 전환

- 성 베드로 대성당은 사용자 지시로 중단·보관한다. `models/st-peters-basilica.md`의 보관 기준과 Git 태그 `archive/st-peters-basilica-v1`을 따른다. 명시적인 재개 지시 전에는 과거 다음 과제를 실행하지 않는다.
- 현재 설계 대상은 아서왕의 카멜롯이며 장기적으로 BrickLink Designer Program 출품용 버전을 검토한다. 사용자는 사자기사성과 함께 놓아도 자연스러운 미니피겨 축척에 더 큰 궁성 규모를 원한다. 사자기사성과 사람·문·계단의 비율이 자연스럽게 맞는 미니피겨 축척을 유지하며 성의 건물·부지 규모를 더 크게 한다. 해자, 오르내리는 성문, 검을 꽂고 뺄 수 있는 성검의 바위, 마상 경기장은 사용자 필수 요구다. 성 안의 평지에 마상 경기장을 두고, 성 건물 내부의 원탁의 전당·왕좌의 전당·예배당과 멀린의 탑을 포함한다. 내부 예배당 포함은 사용자가 명시적으로 지시했다. 사용자가 제공한 세계관과 왕실 상징을 핵심으로 삼되, 카멜롯의 구체적인 건축 배치·크기·부품 수는 아직 확정하지 않았다. 도개교와 별도의 낙하문을 함께 두는 구성은 현재 메인 제안이며 최종 세부 규격은 논의 중이다.
- 카멜롯에는 기존의 미니피겨 일괄 제외 지침을 자동 적용하지 않는다. 출품 부품·색상은 현행 BDP 허용 팔레트를 확인해 정하며 기존 GoBricks 매핑만으로 BDP 사용 가능성을 확정하지 않는다. 카멜롯의 현재 배치와 첫 작업 범위는 아래 전용 절을 따른다.

## 카멜롯 설계 기준과 A–E 첫 과제

### 확정 요구와 디자인 방향

- 원본은 `models/camelot-v1.mpd`, 조립체는 그 안의 내부 FILE로 관리한다. 모델 고유 기록은 실제 모델 작성 시 `models/camelot.md` 하나에 모으며 메인이 편집한다. 별도 작업지시서·관리 파일·실험 MPD를 저장소에 늘리지 않는다.
- 지금은 원하는 규모의 카멜롯 창작 원본을 설계한다. 사자기사성과 함께 놓았을 때 사람·말·문·계단의 비율이 자연스러운 미니피겨 축척을 유지하면서, 건물과 부지의 규모를 키운다. 미니피겨와 내부 예배당은 사용자 명시 요구이므로 기존의 일괄 제외 규칙을 적용하지 않는다.
- 사용자는 수정 콘셉트의 전체 배치와 대략적인 규모 방향에 동의했다. 이미지의 세부 형상을 고정하지 않고 실제 조립 중 조정한다. 첫 콘셉트의 중정이 너무 넓다고 수정했다. 비어 있는 평지를 크게 줄이고 중앙 왕궁과 양쪽 건물 날개를 앞으로 확장한다. 마상 경기장은 성 안 한쪽의 길고 좁은 공간에 넣는다. 중앙 왕궁이 실루엣을 이끌고 여러 탑과 층이 이를 보완한다.
- 멀린의 탑은 바다 쪽 뒤 모서리의 위치와 독립적인 개성을 유지한다. 관측 기구·서재·마법 연구실을 포함하며 일반 방어탑으로 바꾸거나 삭제하지 않는다.
- 원탁 전당은 정면과 양옆을 기둥·아치로 열어 내부가 잘 보이게 한다. 파르테논의 열린 기둥 공간 원리를 참고하되 외형은 중세 석조·목조 전당으로 유지한다. 뒤쪽 왕실 문장 벽과 지지 골조를 남기고 가벼운 파란 지붕을 위로 들어낸다. 이는 이전의 닫힌 앞벽·좁은 입구 중심 지침을 대체한다.
- 필수 요소: 원탁과 구별되는 위험한 자리, 왕좌의 전당, 왕실 문장, 실내 예배당, 멀린의 탑, 마상 경기장과 관람석, 검을 꽂고 뺄 수 있는 성검의 바위, 해자와 그 건너편 평평한 육지, 가동식 성문, 성벽·보행로, 바다와 맞닿은 한쪽 해안이다.
- 입구는 바깥 평지→진입로→해자→도개교→낙하문→작은 중정→왕궁 순서다. 도개교와 낙하문은 독립적으로 움직이는 두 장치로 시험한다. 바깥 평지는 길·숲·마을을 나중에 붙일 수 있게 넓고 평평한 가장자리를 남기며 이번에 외부 마을을 만들지는 않는다.
- 실제 LEGO 부품·색상과 LDraw 형상을 사용한다. 주색은 밝은 회색 석조, 짙은 회색 기단, 파란 계열의 건물 경사지붕·탑 덮개, 소량의 금색·목재색이다. 파란 바탕의 세 왕관은 주 왕실 상징, 붉은 용은 보조 군기다. 원전의 고정 건축물과 창작한 멀린 탑·호수 위치·건물 배치를 혼동하지 않는다.

### 구역별 현실감과 왕궁 내부 — 사용자 합의

- 성벽은 오래됐지만 유지·사용 중인 왕의 성이다. 같은 매끈한 벽을 반복하지 말고 구역의 환경과 사용 흔적을 표현한다. 일부 닳은 여장·깨진 돌·보수 흔적·기단 바위·이끼를 절제해 배치하고 병사 동선·지지 구조는 온전하게 유지한다.
- 정면은 잘 관리된 길과 석벽, 해자 주변은 습한 기단·갈대·풀·이끼, 육지 모서리는 나무·뿌리·바위, 바다 쪽은 거친 암반·낮은 관목·닳은 호안으로 구별한다. 멀린 주변의 나무·덩굴·약초는 신비로운 분위기를 더하되 탑과 개폐 경로를 가리지 않는다.
- 성문 건너편 평지는 단순한 빈 바닥이 아니다. 넓고 비워 둔 중앙 진입로 양옆에 소수의 경비·왕실 깃발·검문 공간과 상인 수레·물품을 구성해 성문 앞의 생활감을 만든다. 바퀴 자국·흙·풀·돌로 마감하고 외부 시장 전체로 확대하지 않는다.
- 21325 대장간은 같은 미니피겨 축척의 지붕 기법 참고다. 기와의 파란 계열 명암·처마 두께·가파른 경사·작은 창과 단차를 활용하되 큰 왕궁의 지붕선은 정돈한다. 작은 건물 날개와 멀린의 탑은 각자의 개성을 살린다. 회색 석조와 평지붕 마감은 바꾸지 않는다.
- 원탁 전당은 열린 기둥·아치 사이로 내부를 볼 수 있게 하고, 지붕만 가볍게 들어내어 인물을 배치할 수 있게 한다. 옛 앞벽을 막은 제출 초안은 보존하되 새 합의를 반영하지 않은 것으로 구분한다.
- 왕궁1층은 높은 천장의 연회장이다. 앞쪽은 기둥과 큰 아치로 거의 열어 두고, 안에는 긴 연회 테이블·벽난로·왕과 왕비의 자리를 구성한다. 그 위2층은 왕실 생활 공간과 정원이며 전체 구조를 받는 뒤 벽·기둥·전달보를 먼저 설계한다.
- 왕궁 전면에는 높은 계단을 올라가는 별도의 왕실 단상을 둔다. 중정을 바라보는 왕과 왕비의 두 의자가 화려한 석조 배경 벽·왕관 문장·깃발을 등진다. 이 외부 알현용 자리는 연회장 내부 자리와 별개다. 중앙 배경과 왕좌로 강조하되 양옆 통로로 뒤 연회장에 진입할 수 있어야 한다.

### 지붕 색·성벽 높낮이·성문·수면의 추가 기준

- 파란 계열 통일은 건물의 박공·경사지붕·탑 덮개 등 실제 지붕을 표현하는 부분에 적용한다. 갈색 지붕 표현을 그대로 가져오지 말고 파란 계열의 깊이·명암으로 정리한다. 같은 계열 안의 차이는 허용하되 여러 지붕 색을 임의로 섞지 않는다.
- 회색 석조 마감·평지붕의 석재 덮개·성벽 보행로·여장과 난간은 유지한다. 내부 FILE 이름에roof가 있다는 이유로 모두 파랗게 칠하지 않는다. 기존 메인 회랑의 회색 마감은 보존한다. 사용자는 지붕 색과 석조 마감을 명시적으로 구분했다.
- 성벽은 전 구간 같은 높이로 반복하지 않는다. 정면의 성문·주요 방어 구간은 높고 웅장하게 하고, 중간 탑·건물·지형에 맞춰 단계적으로 높낮이를 준다. 상부 보행로는 계단·짧은 연결부로 이어져야 하며 미니피겨가 접근하지 못하는 끊긴 장식 벽을 만들지 않는다.
- 바다 쪽은 절벽·호안과 선착장에 맞춰 낮은 성벽·난간·계단을 배치한다. 바다 쪽까지 정면 성문과 같은 높은 벽을 강제하지 않는다. 멀린 탑의 독립적인 높이와 실루엣은 유지한다.
- 정면 성문은 이전24스터드 폭의 낮은 시험안보다 바깥 건물 덩어리와 두 문탑을 확대한다. 첫 검토 범위는 폭32스터드(X24..56), 통과 폭10스터드·높이12브릭이며 실제 가동·말과 수레의 공간을 확인해 조정한다. 중앙 통과축X=40과 바닥 기준은 유지하고 거대 개구 하나로만 웅장함을 표현하지 않는다.
- 해자는 투명한 하늘색(Trans-Light Blue, LDraw43/BrickLink15) 실제 부품을 우선 사용한다. 지원되는 판·타일·브릭 조합과 아래층의 밝은 색으로 투명감과 수심을 표현한다. 이 색이 없는 특정 부품을 있다고 가정하거나 불투명 하늘색을 투명색으로 기록하지 않는다. 바다의 수색은 해자와 자연스럽게 연결하되 아직 같은 표현으로 확정하지 않는다.

### 외곽 방어 성벽 — 사자기사성 기준

- 외곽은10305 사자기사성처럼 병사가 위를 순찰하고 여장 사이에서 방어하는 석조 성곽으로 둘러싼다. 벽·상부 보행로·흉벽과 여장·방어탑·성문을 일관된 두께와 높이 관계로 연결한다. 장식용 담장이나 크게 뚫린 아치 회랑을 외곽 방어 성벽으로 대신하지 않는다.
- 10305 제품 형상에서 확인한 넓은 석조 면·소량의 무늬 벽돌·깊고 좁은 총안·모서리의 곡면 처리·돌출 보행로 아래 받침을 선별해 참고한다. 고딕 창과 장식 아치를 외곽 전체에 반복하는 방식은 기본 성벽 표현으로 채택하지 않는다.
- 성 안쪽 계단·문으로 성벽 위에 실제로 접근할 수 있어야 한다. 보행로는 미니피겨가 서고 이동할 수 있는 폭과 받침을 확보하며, 모서리·문탑·중간 탑에서 보행 동선이 끊기지 않도록 설계한다. 총안·작은 방어 개구·기단 보강은 해당 제품의 실제 조립을 참고한다.
- 중간 첨탑·방어탑·왕궁·멀린의 탑이 만나는 구간에도 기본 석조 성벽의 재료감·여장 리듬을 이어 간다. 탑의 장식이나 높이는 달라질 수 있지만 주변 성곽을 서로 무관한 건물 조각으로 만들지 않는다.
- 바다 쪽 선착장과 배의 접근부는 일반 성벽으로 일률적으로 막지 않는다. 낮은 호안·부두·계단과 성으로 들어가는 출입구를 구성하고, 그 옆과 위의 성벽·탑에 자연스럽게 연결한다. 바다 쪽 모든 경계를 개방하거나 반대로 선착장을 높은 벽으로 차단하지 않는다.
- AI 이미지는 대략적인 배치·규모·분위기를 확인하는 자료다. 이미지의 큰 개구·벽 두께·장식·임의 브릭을 설계 도면처럼 따라 만들지 않는다.10305의 성곽 구조를 주 기준으로21325·10223·910047의 해당 부위 기법을 실제 CAD·설명서·제품 형상으로 확인한다.
- 메인이 먼저 만든234개는 공통 기초와 내부 중정 회랑이다. 이 아치형 구조를 외곽 방어 성벽의 완성 표본으로 확대·복제하지 않는다. 외곽 성벽과 탑 접속은 별도 구조로 설계한다.

### 확정한 개폐 방식 — B·E 지시 우선 적용

- B 원탁 전당: 큰 지붕을 힌지로 뒤집지 않고 위로 들어내는 탈착식으로 만든다. 지붕 전체 또는 약 두 모듈 중 실제 무게·강성·취급에 맞는 구성을 고른다. 닫히면 처마·용마루·기둥 및 뒤쪽 벽선이 정렬된 완전한 열린 전당으로 보여야 한다.
- 처마 아래 착좌 턱과 정렬 접점, 필요한 부분 스터드 체결로 지붕을 받친다. 약한 첨탑·장식을 잡아당겨야 분리되는 구조는 피하고, 지붕을 안전하게 잡는 부분과 위쪽 인양 공간을 확보한다. 샹들리에는 지붕과 함께 들려 원탁 위 접근을 막지 않게 한다.
- 지붕을 뺀 벽·전당 골조와 들어낸 각 지붕·샹들리에는 각각 연결된 조립체여야 한다. 닫힘·분리 과정의 간섭·제거 후 접근을 확인한다. 분리된 지붕을 공중에 띄운 상태를 기본 완성 배치로 저장하지 않는다.
- E 멀린의 탑: 바닥·계단·고정 골조를 지지하는 구조를 남기고 뒤쪽 벽체 한 구간을 세로 힌지축으로 옆으로 펼쳐 여러 층을 볼 수 있게 한다. 무게나 휨 때문에 필요하면 가동 벽체를 높이 방향의 독립 구간으로 나눌 수 있다. 벽을 항상 뚫어 둔 상태를 최종 외관으로 삼지 않는다.
- 열리는 벽 아래에는 닫혔을 때 무게를 받는 턱을 두고, 닫힘 끝에는 위치 정렬과 고정 장치를 둔다. 상부 관측실 지붕은 별도의 탈착 모듈로 만든다. 책장·작업대·계단·관측 기구와 벽의 회전 경로를 실제 형상으로 대조한다.
- 벽체는 닫힘0°·중간45°·열림90°를 첫 검사 자세로 삼고 실제 가능한 최대 각도와 주변 여유를 보고한다. 주변 건물이나 장식에 부딪히지 않도록 탑 뒤/옆 개방 공간을 제안하며 담당 밖 건물·루트 위치를 바꾸지 않는다. 임의 변형이나 고정 부품의 결합 파괴로 여는 모습을 만들지 않는다.
- 기본 제출 상태는 지붕이 착좌하고 멀린 탑의 가동 벽이 닫힌 자세다. 원탁 전당과 연회장의 합의된 기둥·아치 개방면은 그대로 유지한다. 가동 부품의 열린 자세는 검토용 상태로 확인하고 실제 힌지·접점과 개폐 범위를 기록한다. CAD에서 닫힘·간섭을 확인한 것과 실물 손 조작·힌지 유지력·공차 확인을 구분한다.

- 평면 원점은 앞쪽 왼쪽이다. +X는 오른쪽 바다 방향, +Z는 뒤쪽 왕궁 방향, -Y는 위다. 아래 표는 스터드 단위이며 MPD에는20 LDU를 곱한다. 경계의 벽·지형은 담당끼리 중복 소유하지 않는다.

### 제작 방식과 출품용 버전

- 현재는 큰 카멜롯의 창작 원본을 우선한다. 나중에 원본을 보존한 별도 출품용 버전에서 부품·색상·수량을 조정한다. 단순 파일 변환만으로 BDP 적합성이 확보된다고 보고하지 않는다.
- 흔한 실제 LEGO 부품·색상을 우선하며, 성문·왕궁·경기장·해안·탑과 장식은 분리 가능하게 만든다. 장식을 줄여도 골조와 가동 구조는 유지되게 한다. 부품 수는 구역별로 집계하되 아직 최종 제품 수량·가격·출품 적합 판정을 만들지 않는다.
- 카멜롯 검증은 `python3 tools/validate_model.py models/camelot-v1.mpd --sync-state --check-body-overlaps`를 기본으로 하며 연결망·실제 DAT 메시 검사를 담당 범위에 추가한다. 지원되지 않는 가동 부품은 실제 접점으로 따로 대조한다.
- 모델 상태에 `parts_system: "LEGO"`를 명시한다. 이는 GoBricks SKU 없이 실제 형상·ID·색상·변환을 검사하는 창작 모델이며 v0 제품 재구성으로 바꾸지 않는다. BDP 팔레트 확인은 별도다. SKU를 지어내거나 LEGO 부품 번호를 GoBricks 상품 번호로 대신 넣지 않는다.
- 현재 BDP 공식 페이지는 점검 안내를 반환해 현행 부품 수·팔레트를 재확인하지 못했다. 이것은 로컬 설계의 중단 사유가 아니다. 출품용 조정 전에 현행 조건을 확인하며, 지금 수치 상한이나 내부 예배당의 출품 적합성을 확정하지 않는다.

### 현재 공유 원본과 실제 접속 기준

- 메인이 `models/camelot-v1.mpd`에 공통 기초·진입로·내부 회랑234개를 작성했다. 이제 새 원본을 받으면 루트의 `cm-main-shared-court.ldr` 호출과 `cm-main-` FILE, `M-` ID를 보존한다. 초기 빈 브랜치에서 만든 자기 조립체는 자기 FILE·자기 상태만 이 공유 원본에 합친다.
- 공통 기초 범위는 월드X24..48/Z28..44스터드, 받침판 윗면Y=-88 LDU다. 8 LDU 두께의 담당 바닥판/타일을 올리면 공통 바닥 윗면Y=-96이 된다. 실제 형상과 접속은 `models/camelot.md`에 기록한다.
- X32..48/Z28..40스터드에는 메인의 포장 통로가 있고 X26..32/Z28..40에는 지붕 회랑이 있다. 다른 담당은 같은 공간에 바닥·부품을 중복하지 않는다. C 지형의 내부 골조와 공통 기초를 이중으로 만들지 않는다. D는 성검 바위로 이 통로를 막지 않는다.

### 현재 왕실 진입부 접속 — 메인 실제 조립 기준

- 기존234개를 보존한 채 포장24개와 왕실 진입부371개를 추가해 현재629개를 구성한다. 통과축은X40스터드다. 포장 범위X32..48/Z28..40, 계단X34..46/Z40..48, 단상X30..50/Z48..56스터드가 실제 배치다.
- 계단은8단·단높이16 LDU·단깊이20 LDU이며 공통 바닥Y=-96에서 단상 바닥Y=-224로 오른다. 두 왕좌는 중정을 바라보고 배경 벽 양쪽에4스터드 출입 폭을 남겼다. 뒤 연회장은Z56 뒤로 이어지며 해당 바닥을Y=-224로 맞추는 것을 첫 접속안으로 삼는다.
- B의 원탁전당은 별도 로컬 조립체로 검토하고 최종 왕궁 위치·층 높이는 통합 때 결정한다. 새 단계의 외부 계단·단상을 자기 FILE 안에 중복 복제하지 않는다. 상층 침실·정원·연회장 본체는 아직 구현 완료가 아니다.
- D의 성검 바위는 넓어진 중앙 진입로를 막지 않도록 중정 오른쪽의 검토 범위에서 배치한다. C는 이 기초의 실제 접속을 읽고 겹치는 내부 골조를 만들지 않는다. 왕실 표식은 현재 파란 판과 금색 원형 장식 시험이며 완성된 세 왕관 문장으로 보고하지 않는다.

- 초기 브랜치에 카멜롯 MPD가 없다면 자기 조립체가 루트에서 실제 호출되는 완결 MPD를 같은 경로로 만들 수 있다. 상태는 schema3·parts_system LEGO·실제 instances/piece_count와 고유 ID를 사용한다. 가짜 임시 부품이나 빈 골조로 수량을 채우지 않는다. 서로 다른 첫 루트는 메인이 자기 FILE·자기 상태만 모아 통합한다. 공유 원본이 생긴 후 루트의 Type-1 배치는 메인이 관리한다.
- 다른 담당 FILE·부품 ID·파생 상태 의미·공통 정책·검증기를 직접 덮어쓰지 않는다. 공용 형상 누락은 담당이 필요한 부품과 의존 파일만 등록하며, 기존 전체 에셋을 갈아 끼우지 않는다. 공통 도구/모델 기록의 병합은 메인이 관리한다.
- 상태 동기화와 실제 형상·연결·겹침을 확인한다. 미지원 접점은 실제 DAT로 대조하고 따로 명시한다. 가동식 문은 열림·중간·닫힘에서 축·줄/체인 경로·주변 간섭·정지 장치를 확인한다. 줄을 장식으로 달거나 고정 조립체를 회전만 시킨 것을 가동 구조 완성으로 보고하지 않는다.
- 지붕은 제거했을 때 남은 벽과 들어낸 지붕이 각각 연결돼 있어야 한다. 보고용 이미지는 만들지 않으며 시각 판단에 필요한 경우만 확인한다. 배치 검토용 AI 그림은 실제 CAD 배치·부품 수·가동·조립 검증의 근거가 아니다.
- 각자 검토한 변경을 자기 브랜치에 커밋·푸시하고 결과를 사용자에게 보고한다. 메인이 다섯 제출본의 담당 FILE과 상태만 선별해 main에 통합하고 의미 있는 진전에서 사이트에 배포한다. 별도 클라우드 에이전트에 대한 실제 지시 전달은 사용자가 한다.

## 목표와 범위

- 궁극적인 목표는 원하는 외형·구조·가동성을 가진 새로운 모델을 설계하는 것이다. 기존 제품 재구성은 부품과 결합 구조를 익히고 참고 원형을 확보하는 수단이며, 모든 v0의 전체 복원을 창작 설계의 필수 선행 조건으로 두지 않는다. 다만 이미 배정된 재구성 범위를 임의로 축소하거나 완료 처리하지 않는다.
- 실제로 연결된 LEGO 모델을 구현한다. 진행은 새로 연결·수정된 형상과 화면으로 판단한다. 커밋 수, 문서 분량, 누적 부품 수, 검사 통과만으로 설계 진척이나 완성을 주장하지 않는다.
- v0는 원래 LEGO 제품을 재구성한다. GoBricks 취급·SKU와 관계없이 원래 부품·색상을 사용하고 누락 형상은 공용에 등록한다. v0 이외 버전은 기본적으로 확인된 GoBricks 판매 부품·색상을 사용하되, 사용자 지정 LEGO 창작인 카멜롯은 `parts_system: "LEGO"`로 구분하고 아래 전용 기준을 따른다. 가짜 상품 ID·SKU를 넣지 않는다.
- 미니피겨·표지판·명판은 제외한다. 본체·받침·구조 연결 부품과 건축 장식 조각상까지 제외하지 않는다. 이미 있는 배치의 삭제는 해당 사용자 지시를 따른다.
- 사용자가 지정한 모델·버전을 지킨다. 새로 재구성하라는 지시에는 기존 배치를 복사하지 않는다. 공용 형상 재사용은 허용한다. 정상 부위를 기준으로 보정할 때 정상 부위까지 함께 바꾸지 말고 수정 전후 차이를 확인한다.

## 자료와 파일

- 원본은 `models/<model>-v<number>.mpd` 하나이며 조립체는 내부 서브모델로 구성한다. 모델별 범위·남은 문제·유용한 설계 근거는 기존 `models/<model>.md`에 간결하게 정리한다.
- 공용 부품은 `assets/parts/`, 제품별 부품표·판매 대응은 `docs/gobricks-dictionary.json`, 검증된 공통 노하우는 `docs/design-experience.json`을 사용한다. 모델 고유 시행착오는 공통 노하우로 옮기지 않는다.
- 별도 진행 파일·요청서·출처 조사 문서·에이전트 관리 파일을 늘리지 않는다. 반복 작업 일지와 대화 전문도 쌓지 않는다. 원본 형상의 저자·라이선스 주석과 필요한 해시는 유지한다. 별도 출처 이력 작성은 개발의 선행 조건이 아니다.
- 새 모델 MPD·해당 모델 기록·필수 공용 형상과 의존 파일은 승인 없이 추가할 수 있다. 그 밖의 새 관리 파일·폴더는 먼저 사용자와 협의한다.

## 개발 순서

1. 같은 제품·판본의 사용 가능한 CAD가 있으면 먼저 적합성을 확인한다. 다른 제품 CAD를 대상 제품의 재구성으로 바꾸어 부르지 않는다. CAD가 없으면 설명서로 실제 연결된 작은 조립체를 먼저 구현하고 확장한다.
2. 제품 부품표 `instruction_sets[제품번호]`에서 색상·수량·형상 후보를 좁힌다. 거대한 사전 전체를 반복해서 읽거나 부품을 매번 처음부터 검색하지 않는다. 제품·책자·봉지·인쇄 페이지·단계 번호를 구분한다. 부품표의 누락·교차표 미완료만으로 후보를 단정 배제하지 않는다.
3. PDF 도해를 이미지로 열어 호출부와 결합부를 확대한다. 텍스트 추출은 번호 확인의 보조 수단이다. 스터드, 구멍·핀 종류, 구멍 간격, 좌우 금형, 색상과 외곽을 실제 형상과 대조한다. 불명확하면 뒤 페이지·완성도·다른 시점에서 역추적한다.
4. 조립체의 로컬 원점과 축을 정하고 실제 접점으로 상대 배치를 계산한다. 전역 원점 미정은 로컬 조립의 중단 사유가 아니다. 중첩 변환을 합성해 구멍 중심·축·삽입 구간을 비교하며, 부품 원점이 같다는 이유로 결합됐다고 판단하지 않는다.
5. 도해 → 부품 식별 → 접점 계산 → MPD 작성 → 구조 검사 → 화면 대조 → 보정의 작업을 반복한다. 비례·실루엣·복잡한 배치 등 시각 판단이 필요할 때 필요한 시점으로 도해와 실제 형상을 대조한다. 매번 세 시점이나 전후 비교 이미지를 만들지는 않는다. 분리·중복·좌우 반전·바닥 방향을 확인하고 다음 구간으로 확장한다.
6. 불확실한 배치는 근거와 잠정 상태를 표시할 수 있다. 실제로 결정할 수 없는 접점만 보류하고 독립 조립체와 후속 도해 작업을 계속한다. 루트에서 호출되지 않은 로컬 조립체는 미배치로 구분하며 완성 조립 수량에 합치지 않는다. 수량을 늘리기 위한 임의 형상·대체·좌표는 넣지 않는다.

## 새로운 모델의 설계와 실험

- 전체 모델을 동시에 고치기 전에 이번에 해결할 기능과 작은 조립 범위를 정한다. 관절 한 구간, 골반 연결, 받침 접점처럼 독립적으로 확인 가능한 단위부터 설계한다. 작업 전 현재 형상을 Git으로 보존하고 담당 범위 밖의 정상 부위를 바꾸지 않는다.
- 먼저 양쪽 연결 대상과 접점·축·사용 부품을 확인하고 실제 조립체를 MPD 내부 서브모델로 만든다. 시험 구조도 기존 모델 MPD 안에서 관리하며 별도 실험 모델·관리 파일을 늘리지 않는다. 미배치 실험은 미배치 상태로 구분하고 전체 모델에 연결된 것으로 보고하지 않는다.
- 가동 구조는 중립 자세와 작은 양·음 각도에서 연결 유지, 의도한 축의 운동, 외형의 연속성과 주변 간섭 후보를 확인한다. 단순히 하위 모델을 회전시킨 것은 실제 관절 구현이 아니다. 부품 변형·고정 결합 파괴·관절 중심 이동으로 움직임을 흉내 내지 않는다. 확인한 각도와 미확인 범위를 명시한다.
- 작은 조립체의 부품 결합과 외형을 확인한 뒤 해당 구간에 통합하고, 다시 전체 화면에서 검토한다. 성공한 방식만 목·꼬리 등 다른 구간에 확장한다. 기존 구조가 실패한 원인을 해결하지 않고 부품 수나 장식을 늘려 감추지 않는다.
- 작업 범위 안에서 설계·검토·수정을 이어가되 실패한 후보를 반복 조사하는 데 시간을 모두 쓰지 않는다. 서로 다른 접근도 성립하지 않으면 구체적인 접점·부품 제약과 시험 결과를 보고한다. 필요한 경우 사람이 CAD에서 연결 구조를 결정하고 에이전트가 부품 검색·반복 배치·검사를 지원하는 방식으로 전환할 수 있다.
- 재사용 가치는 부품 수보다 확인된 연결 원리·적용 조건에 둔다. 확인한 구조의 유용한 원리는 기존 공통 노하우에 통합하되, 불완전한 조립체를 검증된 공용 구조로 확산하지 않는다. CAD상의 확인과 실물 유지력·강도·하중 검증을 구분한다.

## 건축 창작의 비례와 병렬 설계

- 실측 축척은 전체 배치의 기준이며 모든 부품 치수·창 수·기둥 수를 강제하는 규칙이 아니다. 실루엣, 중심부의 강조, 좌우 균형, 반복 리듬, 열린 공간과 깊이감을 우선한다. 더 닮아 보이게 하는 의도적 확대·축소·반복 수 생략은 허용하되 잘못된 배치와 구분해 모델 기록에 짧게 적는다. 이 원칙을 기존 LEGO 제품 v0의 설명서 재구성에 자동 적용하지 않는다.
- 참고 제품은 해당 부위의 형태·비례·조립 기법이 맞는 것으로 고른다. 돔이 있다는 이유만으로 전체를 참고하거나 다른 제품의 축척을 그대로 섞지 않는다. 설명서의 실제 조립과 화면을 확인하고 가져올 기법·가져오지 않을 외형을 구분한다. 목표는 기존 LEGO 제품과 비교해도 설득력 있는 외형이며 크기·부품 수만으로 달성됐다고 판단하지 않는다.
- 표현이나 부품 조합 때문에 축척 조정이 필요하면 축소보다 확대를 우선 검토한다. 이는 변경 허가가 아니라 검토 방향이다. 합의한 기본 축척을 임의 변경하지 않고 구체적인 비교 결과가 생겼을 때 제안한다.
- 여러 에이전트는 건축 구역과 MPD 내부 FILE 섹션별로 담당한다. 메인이 전체 좌표계·접속 위치·기준 높이·공용 모듈과 변경 금지 범위를 정한다. 규격 확정 전에는 담당 구역의 로컬 조립 표본까지만 만들며 전체 건물 배치를 임의 확장하지 않는다. 메인이 루트 배치·최종 상태·공통 사전을 통합하고 각 에이전트는 다른 담당 섹션을 덮어쓰지 않는다. 지시와 결과 전달은 사용자가 맡는다.

## 도구와 공용 부품

- 기존 형상이 없으면 담당 에이전트가 직접 확보·등록한다. 메인 에이전트나 환경 재게시를 기다리지 않는다. 기존 공용 형상을 일괄 재추출·삭제·덮어쓰지 않는다. 원점·축·치수의 변경은 다른 모델에 미치는 영향을 확인하고 사용자에게 알린다.
- 공식 ZIP에서 추가할 때는 `python3 tools/prepare_geometry.py <complete.zip> --parts <부품번호> ...`를 사용한다. 지정 부품과 의존 파일만 추가하며 기존 파일·해시와 의존성을 먼저 확인한다. 필요한 기존 사전의 형상 연결·제품 가용성도 함께 갱신한다. 형상 등록과 상품 판매 대응은 별개다.
- schema 3 MPD 상태는 본문에서 파생한다. `python3 tools/validate_model.py <모델.mpd> --sync-state`로 ID·루트 수량·합성 좌표·미배치 상태를 갱신하고 검사한다. 상태 갱신만 필요하면 `--sync-only`를 함께 사용한다. 자동 갱신은 형상·목표 치수·조립 검증 판정을 수정하지 않는다.
- 상태 자동 갱신은 schema 3만 지원한다. 반복 호출 때문에 물리 부품 ID가 모호하면 저장하지 않고 실패하므로 각 배치의 ID를 구분한다. schema 4 등 미지원 모델을 도구에 맞추려고 변환·재작성하지 말고 지원되는 구조 검사를 수행한다.
- 해시가 다르면 의도한 수정과 병합 양쪽을 확인한다. 실제 파일에 맞춰 해시만 바꾸어 통과시키지 않는다. 확인된 원본 복원 또는 근거 있는 수정 후 관련 해시를 갱신한다.

## 작업 지속과 검증

- 최신화·이미지 열람·부품 등록·ID 보완·첫 검사 실패·중간 커밋은 작업 종료 조건이 아니다. 해결 가능한 오류는 고치고 독립 작업도 계속한다. 같은 조사와 기록만 반복하며 실제 배치가 진전되지 않으면 후보 검색 범위·열람 페이지·접점 계산·조립 단위 등 접근 방법을 바꾼다. 이미 수행하지 않은 조사를 불가능한 장애로 표현하지 않는다.
- 합의한 과제가 남아 있는데 한 조립체나 몇 개 부품을 추가했다는 이유만으로 응답을 끝내지 않는다. 사용자가 관절 한 구간처럼 작은 과제를 지정한 경우에는 그 범위의 설계·검토·보고를 마치면 해당 과제 완료이며, 임의로 전신 수정까지 확대하지 않는다. 중간 진행을 알리면서 승인된 전체 범위를 이어간다. 전체 범위가 끝났거나 사용자가 중단했거나 남은 모든 작업이 실제 장애로 막혔을 때 종료한다. 실행 한계로 미완료 종료 시 실제 저장된 변경과 다음 재개 지점을 정확히 적고, 종료 후 자동으로 작업이 계속된다고 말하지 않는다.
- 곡면·창틀·아치·힌지 주변을 바꾼 지원 모델은 `--check-mesh-crossings --instance-prefix B-`로 담당 실제 DAT 표면을 추가 검사한다. Blender를 사용하며 이미지는 생성하지 않는다. 이름이 확인된 스터드·힌지 체결 쌍을 제외한 표면 횡단 후보를 보고한다. 비다양체 내부 포함·침투 부피·실물 공차는 판정하지 않는다. 출력 앞부분의 데이터 통과와 전체 명령의 성공 종료를 혼동하지 않는다.
- 직육면체 겹침 0건은 검사에서 빠진 창틀·아치·경사·원형 기둥·힌지의 무간섭을 뜻하지 않는다. 변경 부위와 주변의 실제 형상도 대조하고, 이전에 지적된 ID 쌍만 고쳐 다른 부품으로 교차가 옮겨 가지 않았는지 확인한다.
- 형상 참조·ID·수량·변환, 시각적 조립 상태, 상품 매핑, 실제 삽입·가동·강도·하중을 구분한다. 실물 미검증은 디지털 모델링의 중단 사유가 아니며, 디지털 검사 통과가 실물 검증을 대신하지도 않는다.
- 지원 모델은 `python3 tools/validate_model.py <모델.mpd>`로 검사한다. v0에 GoBricks 매핑을 요구하지 않는다. 미지원 스키마나 도구 오류는 영향 검사만 구분하고 가능한 구조 검사와 모델링을 계속한다. 알려진 실패를 의미 없이 반복하거나 검사 기준을 약화해 통과시키지 않는다.
- 지원 부품의 담당 전체 연결은 `--check-stud-connectivity --instance-prefix B- --expect-stud-components 1`로 추가 확인한다. 독립 비교 표본이 둘이면 기대 개수도 둘이며 각 성분에 어떤 부품이 들어가는지 확인한다. 새 부품 몇 개의 접점이나 겹침 0건만으로 전체 연결을 주장하지 않는다. 이 검사는 본문에서 계산한 명목 스터드·힌지 연결망이며 미지원 부품·옆면 결합은 별도 검토한다. 기대 개수를 바꿔 실패를 감추거나 미지원 연결 조사를 중단하지 않는다.
- 이미지는 설계 판단에 필요한 경우에만 만들고 확인한다. 단순 좌표·상태 보정은 수치 검사로 확인할 수 있으며, 보고용 이미지 생성·저장·전달을 필수 절차로 두지 않는다. 사용자의 검토가 필요한 진전은 메인이 판단해 가끔 사이트에 배포해 알린다. 뷰어 코드 변경에는 관련 브라우저 테스트를 수행한다. 뷰어 빌드 성공을 모델 조립 성공으로 보고하지 않는다.

## 조사·판단 답변 기준

- 사용자가 조사·비교·가능성·사업성·실행 여부를 물으면, 근거상 가능성이 높은 쪽으로 판단을 내리고 결론부터 말한다. “현실적으로 어렵다”, “어렵지만 이 방식이면 가능성이 높다”, “진행해도 된다고 판단한다”처럼 사용자가 다음 행동을 결정할 수 있게 답한다.
- “될 수도 있고 안 될 수도 있다”, “경우에 따라 다르다”는 가능성 나열만으로 답을 끝내거나 판단을 회피하지 않는다. 가장 유력한 결론과 그 이유, 결론을 실제로 바꿀 핵심 조건만 설명한다. 어렵거나 사업성이 낮다고 판단하면 솔직하게 말하고 근거 없는 낙관도 피한다.
- 사용자가 명시한 실제 계획과 조건을 기준으로 답한다. 이미 이해한 상식적 주의사항이나 질문 범위 밖의 가정을 반복해 결론을 흐리지 않는다. 역사적 건축물을 직접 브릭으로 설계·판매하는 질문도 그 전제에 집중하고, 요청하지 않은 로고·타인 자료 이용 등의 다른 사례로 답을 돌리지 않는다.
- 명확한 판단과 사실 확정은 구분한다. 확인되지 않은 법률·권리·기술 사실을 단정하거나 확률을 만들어내지 않는다. 필요한 사실은 먼저 조사하고, 정보가 부족하면 현재 근거로 내리는 잠정 판단을 분명히 제시한 뒤 결론에 중요한 미확인 사항만 짧게 밝힌다. 자료 부족 자체가 판단을 막는 경우에는 부족한 핵심 사실과 확인 방법을 구체적으로 말한다.

## 여러 에이전트와 Git

- 개별 에이전트는 담당 모델·버전과 자기 브랜치에서 작업한다. 다른 모델을 수정하지 않는다. 같은 모델 기록·공용 부품·사전의 동시 수정은 사용자가 조율한다. 별도 클라우드 에이전트 사이의 지시 전달도 사용자가 맡는다.
- 작업 시작과 통합 전에 로컬 변경을 확인·보존하고 최신 `origin/main`을 가져와 작업 브랜치에 반영한 뒤 정책과 모델 기록을 읽는다. 원격 추적 ref가 갱신되지 않는 환경에서는 `git fetch origin refs/heads/main:refs/remotes/origin/main`으로 명시적으로 최신화한다. `FETCH_HEAD`만 갱신된 상태를 최신 `origin/main`으로 오인하지 않는다. 최신 main 반영을 위해 환경 재게시·새 초안을 요구하지 않는다. 최신화는 개발을 이어가기 위한 단계다.
- 자기 변경만 선별해 커밋한다. 다른 작업을 덮는 강제 푸시·일괄 복원·무단 삭제나 공유 이력 재작성은 하지 않는다. 충돌은 양쪽의 필요한 변경을 보존하고 의도가 불명확한 부분만 질문한다. 별도 worktree·관리 파일을 늘리지 않는다.
- 개별 에이전트는 자기 브랜치에 검증한 변경을 커밋·푸시한다. 메인 에이전트가 검토·main 통합·사이트 배포를 맡는다. 브랜치 푸시, main 통합, 사이트 배포, 클라우드 환경 게시를 구분한다.
- 메인 루트 보존은 Type-1 조립체 호출의 위치·회전을 보존한다는 뜻이다. 담당 수정으로 바뀐 ID·합성 좌표·수량·SKU 수·가격·관측 외곽 등 파생 상태는 실제 본문에 맞게 갱신한다. 낡은 상태 집계를 남기는 것을 담당 범위 보존으로 해석하지 않는다.
- 보고에는 이번에 실제 바뀐 형상·연결, 완료 범위, 미해결 항목, 검사 한계와 커밋을 적는다. 문서·병합만 바뀐 커밋은 설계 개선으로 보고하지 않는다. 공통 적용이 확인된 팁만 메인이 기존 공통 노하우에 통합한다.
- 상태 질문에는 먼저 답하고 기존 작업을 이어간다. 사용자가 토론만 요청한 경우 파일은 수정하지 않는다.
