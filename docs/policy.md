# BRICK 프로젝트 정책

## 목적

고브릭스(GoBricks) 부품을 사용하는 독자적인 모델을 설계한다. 설명서 재구성용 버전 0은 원래 부품 구성을 기록하며 고브릭스 판매 여부로 부품을 제외하지 않는다.

## 파일·폴더 추가 전 보고

새로운 모델을 작업하면서 `models`에 해당 모델의 작업파일을 만드는 경우만 예외로 한다. 그 외에는 위치나 용도에 관계없이 모든 새 파일·폴더를 만들기 전에 사용자에게 이름·목적·필요성을 보고한다. 도구, 뷰어 소스, 테스트, 설정, 형상 자산, 다운로드·추출 파일, 임시 파일과 자동 생성 출력도 예외로 취급하지 않는다. 명령이나 설치·빌드가 파일을 추가하는 경우도 실행 전에 예상 범위를 보고한다. 기존 파일 수정은 기존 작업 범위에서 진행한다. 공통 문서 추가는 기존 규칙대로 사용자 승인을 받은 뒤 수행한다.

## 공통 자료

`docs`에는 다음 세 파일만 둔다. 파일을 추가해야 할 때는 반드시 사용자에게 먼저 물어보고 승인을 받은 뒤 추가한다. 기존 파일의 내용은 작업에 따라 갱신한다.

- `policy.md`: 프로젝트 목적과 작업 원칙.
- `gobricks-dictionary.json`: 어시스턴트가 검색·선택할 수 있는 부품 사전.
- `design-experience.json`: 모델을 넘어 재사용할 설계 경험과 결합 사례.

부품 사전에는 식별 번호, 형상 참조, 치수·좌표 기준, 연결 위치·방향·종류, 색상, 출처와 확인 상태를 저장한다. 확보한 정보를 재사용하고 누락·변경 정보만 추가 확인한다. 고브릭스에서의 판매 확인과 기하학적 호환성 검증은 구분한다. 확인하지 않은 정보를 추정하여 확정 데이터로 넣지 않는다.

공통 설계 경험에는 해결할 문제, 적용 조건, 방법, 결과와 근거, 검증 수준·한계를 남긴다. 결합뿐 아니라 골격 비례·곡면 표현·관절·균형·지지 구조도 다룬다. 모델에만 해당하는 결과는 모델별 기록에 둔다. 설명서 재구성은 사용자가 지정한 전체 페이지와 조립 단계를 대상으로 한다. 출처와 확인 범위를 기록한다. 형상 검토와 실물 조립 검증을 구분한다.

## 모델 원본

개별 설계는 최종안 확정 전까지 `models/<english-model-name>-v<number>.mpd`로 버전을 나눠 관리한다. 현재 티라노 설계가 `tyrannosaurus-v1.mpd`이며 그 이전 설계는 비교 버전으로 복원하지 않는다. 이후 설계 변경은 v2, v3처럼 새 파일에 저장하고 이전 버전을 덮어쓰거나 삭제하지 않는다. 단순 문서·뷰어 수정은 모델 버전을 늘리지 않는다. 최종안은 사용자 승인 후 확정하며 이전 파일 삭제도 별도 지시를 따른다.

버전 0의 작업 범위는 1권 220쪽·2권 148쪽·3권 120쪽의 총 488쪽 전체다. 미니피겨·명판·하단 장식은 구현에서 제외하되 부품표에 사유를 남긴다. 받침판 상세가 막히면 넓은 빨간 대체 판을 사용하고 본체를 우선한다. 각 페이지를 실제로 검토하고 조립 단계는 부품 등록·배치 구현·검증 또는 구체적인 미해결 기록까지 처리한다. 과거의 일부 페이지만 참고한 외형 근사 방식을 폐기한다. 화면 명칭은 버전 0으로 한다. 각 배치에 권·페이지·단계·부품 번호·색상·위치·회전과 확인 상태를 연결한다. 누락 형상은 확보 또는 구현하고, 대체 부품을 원래 부품과 같다고 처리하지 않는다. 모든 단계·부품·배치를 대조하기 전에는 100% 구현이나 완료라고 보고하지 않는다. 작업용 LDR 체크포인트는 models 안에서 관리하고, 검증 중인 체크포인트를 완성 버전으로 배포하지 않는다.

각 버전의 형상 원본은 MPD 한 파일로 유지하고 내부 서브모델로 구조를 나눈다. `models/<english-model-name>.md` 하나에서 기준 제품·버전별 핵심 차이·실패와 개선 근거·미해결 문제를 관리한다. MPD에는 버전 번호와 배치·부품표 등 기계가 사용하는 상태를 유지한다. 모델 버전과 파일 내용 해시는 구분하며, 뷰어 목록에서는 사람이 읽는 v1·v2를 표시하고 캐시 처리에는 내용 해시를 사용한다.

공통 부품 형상은 모델마다 복제하지 않고 별도 형상 자산을 참조한다. 형상 자산은 검색 사전이나 정책 문서를 추가하는 것과 구분한다. MPD 이외의 추가 원본 형식이 필요하면 먼저 사용자와 협의한다. 미리보기·렌더 등 재생성 가능한 산출물을 원본으로 취급하지 않는다.

## 진행 원칙

요청한 모델의 요구를 파악하고 부품 사전, 해당 모델의 Markdown 기록, 관련 공통 설계 경험을 읽고 설계한다. 새로 확인한 부품 정보와 재사용 가능한 검증 사례는 공통 자료에 반영한다. 저장된 자료가 늘어나는 것을 모델 자체의 재학습으로 표현하지 않는다. 검증하지 않은 모델을 완성 또는 조립 가능하다고 선언하지 않는다.

## 설계 토론과 경험 관리

확정된 사용자 지시·재사용 가능한 실패 원인·유효한 개선점은 별도 기록 지시를 기다리지 않고 해당 작업 안에서 기존 정책·모델 기록·공통 경험에 반영한다. 대화 전문이나 단순 진행 로그는 남기지 않고 중복·낡은 내용은 갱신한다. 기록 변경도 완료 보고에 포함한다.

사용자가 지정한 참고 제품은 외형·가동성·지지 구조의 최소 비교 기준이다. 실제 형상의 완성도를 우선하고, 그다음 가동성·자세 유지·결합 안정성, 같은 품질에서의 부품 효율을 평가한다. 부품 수를 맞추기 위해 불필요한 부품을 넣지 않는다. 실제 자료를 확인해 기준을 정하며, 가동 부위·각도·지지대 수 등을 추정해 확정하지 않는다. 모든 부위를 가동할 필요는 없지만 참고 제품보다 다양한 자세를 표현하는 것을 목표로 한다. 자립이 가능하면 우선 검토하되 불가능한 조건을 강요하지 않는다. 개선을 위해 다른 품질을 떨어뜨리는 타협은 사용자와 먼저 논의한다.

모델별 기록에는 다음 설계 결정에 영향을 주는 내용만 남긴다. 문제 → 시도 → 관찰 결과 → 채택·폐기 이유를 짧게 기록하고, 아직 시도하지 않은 방법은 제안으로 표시한다. 일일 일지·대화 전문·사소한 변경·반복 설명은 저장하지 않는다. 오래된 결론은 갱신하거나 삭제하되 재발 방지에 필요한 실패 근거는 보존한다.

공통 경험으로 올릴 때는 다른 모델에 적용할 수 있는 조건과 근거가 있어야 한다. 모델별 실패 전체를 복제하지 않는다. 사용자 평가, 추정, 계산·형상 확인, 실물 검증을 구분하고 성공이 확인되지 않은 사례를 검증된 해법으로 표시하지 않는다. 작업 시작 시 관련 기록 확인 → 허가된 설계·비교 검토 → 유용한 결과만 기록 갱신 순서를 따른다. 파일이 늘어난 것을 자동 학습이나 성능 향상으로 표현하지 않는다.

## 수집·설계 순서

독자 설계에서는 고브릭스의 판매 부품 목록을 먼저 확보하고 형상 종류와 색상 변형을 구분한다. 버전 0 재구성은 이 판매 목록에 제한받지 않고 설명서의 원래 부품을 등록·구현한다. 전체 목록 수집과 형상·연결 정보의 정밀화를 구분하며, 모델에 필요한 부품부터 정밀화한다. 이후 필요한 구조의 설명서를 참고해 설계하고 재사용 가능한 결합 사례를 남긴다. 전체 수량과 수집 완료 여부는 출처와 페이지 범위를 확인한 경우에만 확정한다. 뷰어는 기존 공개 검토 사이트를 사용한다.

가격은 색상별 판매 상품 기준으로 통화·확인 시점·구매 단위를 구분한다. 실제 묶음 가격이 확인된 경우에만 묶음 수량·총액·개당 환산가와 출처를 기록한다. 주문 한도를 묶음 수량으로 해석하거나 수량 할인을 추정하지 않는다. 공개 낱개 단가 합계와 대량 구매 원가를 구분하고, 묶음 조건 조사가 오래 걸리면 미확인으로 남겨 부품 수집을 우선한다.

## 현재 개발·검토 방법

기존 체크아웃을 사용하며 별도 Git worktree를 만들지 않는다. `viewer`에서 `npm ci --ignore-scripts` 후 `npm run build`로 모델과 허용된 형상 자산을 포함한 정적 뷰어를 만든다. 로컬 개발은 같은 디렉터리에서 `npm run dev`로 시작한다. `models`의 MPD와 `assets`가 뷰어 배포물에 포함되며 공개 사이트 방문자는 이를 내려받을 수 있다. 사용자가 승인한 공개 저장소와 GitHub Pages를 사용한다. 모델 검증은 저장소 루트에서 `python3 tools/validate_model.py models/tyrannosaurus-v1.mpd`, 뷰어 검증은 `viewer`에서 `npx playwright test`로 수행한다. 모델 원본은 MPD 파일에서 직접 관리하며, 일회성 티라노 생성 스크립트와 이전 스페이스 작업 기록은 보관하지 않는다.

## 도구 목록과 재사용 원칙

작업을 시작하기 전에 이 목록과 관련 도구 파일 맨 위의 기능 설명을 확인한다. 아래 명령은 저장소 루트에서 실행한다. `<...>`는 실제 입력 경로로 바꾼다. 설명을 확인하는 목적으로 도구를 무작정 실행하지 않는다.

| 현재 파일 | 용도 | 실행 방법 | 변경 대상 |
| --- | --- | --- | --- |
| `tools/collect_gobricks.py` | 공식 판매 목록·가격 수집 | `python3 tools/collect_gobricks.py --cache <수집 폴더>` | 지정 폴더의 페이지 JSON |
| `tools/build_gobricks_dictionary.py` | 수집 자료 검사·사전 생성 | `python3 tools/build_gobricks_dictionary.py --cache <수집 폴더>` | 부품 사전 전체, 저장 중 임시 파일 |
| `tools/prepare_geometry.py` | 필요한 형상 추출·경로 변환 | `python3 tools/prepare_geometry.py <complete.zip 경로>` | 에셋 형상·색상과 에셋 정책 내부 목록 |
| `tools/enrich_dictionary.py` | 치수·선택된 연결 정보 보강 | `python3 tools/enrich_dictionary.py` | 부품 사전의 형상 관련 정보 |
| `tools/validate_model.py` | 지정 MPD·에셋·사전 검사 | `python3 tools/validate_model.py models/tyrannosaurus-v1.mpd` | 없음; 콘솔 출력만 수행 |

### 실행 순서와 현재 한계

판매 정보가 필요할 때만 수집 → 사전 생성 순서로 실행한다. 사전 생성은 기존 형상 보강 정보를 초기화하므로 단순 가격 갱신 목적으로 무작정 실행하지 않는다. 기존 보강 정보의 보존·복원 방법을 먼저 검토한다.

새 형상이 필요할 때만 형상 추출 → 사전 형상 보강 → 모델 검증 순서로 진행한다. 형상 추출은 코드의 TOP 목록을 기준으로 불필요한 형상을 삭제하므로 다른 모델이 사용하는 형상도 포함하는지 확인한다. 형상 추출 TOP과 사전 보강 mapping의 지원 범위는 서로 다르므로 해당 코드와 에셋 목록에서 확인한다. 형상 확보와 판매 대응·색상·연결 검증을 구분한다.

검증 도구는 지정한 BRICK schema 3 MPD의 계층 변환·상태·수량·회전·SKU·형상 무결성을 검사한다. 다른 모델에도 같은 도구를 사용하고, 지원하지 않는 형식은 명시적으로 거부한다. `--check-body-overlaps`는 직육면체 몸체 간섭만 검사한다. 전체 연결·정밀 간섭·실물 조립을 검증하지 않으며 통과를 조립 가능 판정으로 표현하지 않는다.

### 유지 관리 규칙

- 기존 도구를 먼저 검색하고 기능·입출력·부작용을 읽은 후 재사용한다. 같은 기능의 도구를 매번 새로 만들지 않는다.
- 기능이 부족하면 기존 도구를 개선한다. 새 도구가 필요할 때는 기존 도구로 처리할 수 없는 이유와 파일명·목적을 먼저 보고한다.
- 파일명은 동작과 대상을 드러내도록 짓는다. 모델별 검증 스크립트를 늘리지 않는다. 파일을 나누거나 합치는 기준은 기능과 재사용성이다.
- 모든 도구 파일의 맨 위에 기능·입력·출력·실행 예시·주의사항·검증 한계를 한국어로 설명한다.
- 도구의 이름·기능·명령·출력 경로가 바뀌면 이 표와 해당 파일 상단 설명, 호출하는 코드도 함께 갱신한다.
- 캐시·임시 파일·형상·빌드 결과를 만드는 경우에도 생성 범위를 실행 전에 보고한다. 사용자가 승인한 새 모델 작업파일만 기존 예외를 적용한다.
- 도움말 지원 여부를 확인한다. 현재 수집·사전 생성·형상 추출은 `--help`를 지원하지만, 형상 보강은 지원하지 않는다. 공통 모델 검증은 `--help`를 지원한다.

## 뷰어 사용 규칙

상단 배너 없이 왼쪽 메뉴에 조작을 모으고 글자 크기를 동일하게 유지한다. 모델 선택은 즉시 불러오므로 별도 View 버튼을 두지 않는다. 부품 선택·숨기기·숨김 초기화와 전체 보기·옆모습·정면·기본 자세·지지대 표시 기능은 유지한다. 화면을 단순화해 달라는 요청을 기능 삭제로 확대하지 않는다. 모델 목록과 실제 MPD의 내용 해시를 대조해 이전 캐시를 새 버전으로 표시하지 않는다.

## 모델 품질과 완료 보고

참고 제품의 외형을 충분히 재현하지 못한 모델은 비교 기준이나 완성품으로 보고하지 않는다. 같은 시점에서 두개골의 입체 형상·빈 공간, 갈비뼈 곡선과 길이, 척추·골반·사지·꼬리의 비례를 실제 참고 도해와 비교하고 차이를 명시한다. 자동 배치와 부품 수·파일 검사는 외형 품질이나 조립 가능성의 증거가 아니다. 관절 슬라이더의 화면상 회전과 실제 가동 범위·결합력·안정성을 구분한다. 부족한 부분은 완료라고 포장하지 않고 확인된 결과와 한계를 보고한다.

## 작업 시작·지속·종료 기준

- 토론·질문·의견 요청에는 설명만 제공한다. 파일 수정·생성·배포 지시로 확대하지 않는다.
- 명시적으로 승인한 작업은 합의한 전체 범위를 처리한다. 일부 페이지·몇 단계·중간 보고·파일 저장을 임의의 종료 기준으로 삼지 않는다. 기록 정리 승인을 모델 형상 수정 승인으로 확대하지 않는다.
- 진행 중 질문·상태 요청에는 답하고 원래 작업을 이어간다. 사용자의 명시적인 중단·취소 또는 양립할 수 없는 새 지시가 있어야 기존 작업을 중단한다.
- 해결하지 못한 개별 항목은 기록하고, 사용자 확인이 필요한 경우 질문한다. 현재 실행 순서·질문 기준을 따른다. 전체 범위를 검토해 수행 가능한 항목을 처리한 경우, 사용자가 중단한 경우, 또는 남은 모든 항목에 공통으로 적용되는 실제 장애가 있는 경우에 종료 이유를 보고한다. 공통 장애를 주장할 때에는 영향 범위와 시도 결과를 제시한다.
- 응답 종료 후에는 작업이 자동으로 계속되지 않는다. 백그라운드 작업을 실제로 실행하지 않았으면 계속 진행 중이라고 말하지 않는다.
- 수행 가능성을 확인하기 전에 무조건 완수·100% 정확성을 약속하지 않는다. 설명서의 모든 단계·수량·부품·색상·좌표·회전·결합을 대조할 수 있어야 버전 0 완료를 보고한다. 확인할 수 없는 항목을 추정해서 검증 완료로 처리하지 않는다.
- 작업 중 확인한 지식은 별도 지시를 기다리지 않고 기록한다. 티라노 전용 지식은 models/tyrannosaurus.md, 재사용 가능한 원리·조건·근거·한계는 docs/design-experience.json, 필수 작업 규칙은 이 정책에 관리한다. 중복·대화 전문·단순 일지는 쌓지 않는다.

## 버전 0 실행 순서와 질문 기준

매 조립 단계는 두 작업을 반복한다. (1) 해당 단계의 부품 그림에서 종류·색상·수량을 먼저 식별하고 기존 사전·형상을 확인하며, 누락 부품은 등록·구현한다. (2) 같은 단계의 조립 그림에서 위치·방향·연결점을 대조하여 배치한다. 설명서로 확인된 항목은 확인으로 기록한다. 보이지 않는 내부 몰드의 미세 차이를 부품 식별·외형·배치 전체의 미확정 사유로 확대하거나 순차 조립의 중단 사유로 삼지 않는다. 실제 배치 충돌이나 연결 관계를 해결하지 못한 경우에만 그 구체적인 문제를 제시한다. 도해 대조와 실물 검증은 구분한다.

1. 매 설명서 단계에서 먼저 그 단계의 부품 종류·색상·수량과 등록 여부를 확인한다. 미등록 부품을 등록·구현한 뒤 즉시 같은 단계의 배치 작업으로 이어간다. 전체 모델의 모든 부품을 먼저 완벽하게 끝내야 조립할 수 있다는 조건을 두지 않는다. 미니피겨·하단 장식은 제외하며, 받침판만 승인된 빨간 대체를 허용한다.
2. 2단계는 설명서 1페이지부터 한 장씩 순서대로 검토·조립하는 것이다. 모든 권과 페이지를 처리 대상으로 유지하고, 본체 이외의 페이지는 제외 사유를 기록한다. 각 권 안에서는 앞으로 점프해 임의의 하위 조립체를 먼저 만들지 않는다. 사용자가 승인한 1·2·3권 병렬 작업은 독립된 조립체를 권별 로컬 좌표로 순차 구현한다. 담당별 작업파일을 분리하고 공통 형상·사전·진행 기록과 최종 결합은 주 담당자가 통합한다. 권 간 결합 위치·방향·연결 부품을 기록하고 통합 전에는 완성 조립체로 처리하지 않는다.
3. 부품 식별·색상·형상·위치·회전을 확정할 수 없는 경우 가능한 자료 대조와 형상 확인을 수행한다. 그래도 막히면 해당 권·페이지·단계·부품, 확인한 근거와 구체적인 질문을 사용자에게 제시한다. 빨간 대체 승인은 받침판에 한정한다. 장식은 생략할 수 있지만 공룡 본체의 뼈대·관절·연결 부품은 생략하거나 임의 대체하지 않는다. 본체가 막히면 자료를 대조하고 해결하지 못한 구체적인 항목을 질문한다. 해결 전에는 해당 단계를 완료로 처리하지 않는다. 대체 위치·원래 부품·이유·미검증 기능을 모델 기록과 진행 데이터에 남긴다. 원래부터 빨간 부품과 대체품은 기록으로도 구분한다. 답변이 필요 없는 독립적인 부품 조사·검사는 계속할 수 있다.
4. 기존의 미해결 자동 건너뛰기·다른 페이지 선행 규칙은 위 사용자 지시로 대체한다. 이전 초안은 검증 완료로 계산하지 않는다.
5. 완료 보고는 실제 확인한 범위에 한정한다. 전체 부품 형상 확보·순차 조립·검증이 끝나야 완성으로 보고한다. 실패·수정 근거는 모델 전용 기록과 공통 노하우로 구분해 기존 파일을 갱신한다. 중복·오래된 정책은 통합하거나 삭제한다.

## 받침대 범위 갱신

사용자 추가 지시에 따라 원래 설명서의 받침대도 구현한다. 미니피겨와 인쇄된 명판 타일만 제외한다. 명판 고정용 갈색28802브래킷2개(요소6168623)는 포함해 원래 위치에 조립한다. 3권 마지막 부품표로 요소 번호·설계 번호를 식별하고 실제 조립 페이지에 따라 배치한다. 기존 빨간 대체 받침판은 원래 받침대의 조립·연결 확인 후 교체한다. 받침대 작업은 하위 에이전트, 공룡 본체 최종 통합은 주 담당자가 맡는다.
