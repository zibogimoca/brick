# BRICK 프로젝트 정책

## 목적

고브릭스(GoBricks) 부품을 사용하는 레고 방식의 독자적인 모델을 설계한다.

## 파일·폴더 추가 전 보고

새로운 모델을 작업하면서 `models`에 해당 모델의 작업파일을 만드는 경우만 예외로 한다. 그 외에는 위치나 용도에 관계없이 모든 새 파일·폴더를 만들기 전에 사용자에게 이름·목적·필요성을 보고한다. 도구, 뷰어 소스, 테스트, 설정, 형상 자산, 다운로드·추출 파일, 임시 파일과 자동 생성 출력도 예외로 취급하지 않는다. 명령이나 설치·빌드가 파일을 추가하는 경우도 실행 전에 예상 범위를 보고한다. 기존 파일 수정은 기존 작업 범위에서 진행한다. 공통 문서 추가는 기존 규칙대로 사용자 승인을 받은 뒤 수행한다.

## 공통 자료

`docs`에는 다음 세 파일만 둔다. 파일을 추가해야 할 때는 반드시 사용자에게 먼저 물어보고 승인을 받은 뒤 추가한다. 기존 파일의 내용은 작업에 따라 갱신한다.

- `policy.md`: 프로젝트 목적과 작업 원칙.
- `gobricks-dictionary.json`: 어시스턴트가 검색·선택할 수 있는 부품 사전.
- `connection-examples.json`: 재사용할 결합·구조 사례.

부품 사전에는 식별 번호, 형상 참조, 치수·좌표 기준, 연결 위치·방향·종류, 색상, 출처와 확인 상태를 저장한다. 확보한 정보를 재사용하고 누락·변경 정보만 추가 확인한다. 고브릭스에서의 판매 확인과 기하학적 호환성 검증은 구분한다. 확인하지 않은 정보를 추정하여 확정 데이터로 넣지 않는다.

결합 사례에는 해결할 문제, 부품과 상대 배치, 적용 조건, 출처, 검증 방법·결과·한계를 남긴다. 공개 설명서는 결합 원리를 이해하는 참고자료로 사용하고 설명서 전체나 타인의 모델을 그대로 복제해 수집하지 않는다. 형상 검토와 실물 조립 검증을 구분한다.

## 모델 원본

개별 설계는 `models/<english-model-name>.mpd`로 관리한다. 번호보다 알아볼 수 있는 모델명을 사용한다. 예를 들어 티라노는 `tyrannosaurus.mpd`로 저장한다. 모델별 원본은 한 파일을 기본으로 하고, MPD 내부 서브모델로 구조를 나눈다. 목표·요구 사항·결정 사항·미해결 문제·검증 결과·다음 행동은 같은 파일의 LDraw 주석에 기록한다.

공통 부품 형상은 모델마다 복제하지 않고 별도 형상 자산을 참조한다. 형상 자산은 검색 사전이나 정책 문서를 추가하는 것과 구분한다. 추가 원본 형식이 필요해 한 파일 원칙을 바꿔야 할 때는 먼저 사용자와 협의한다. 미리보기·렌더 등 재생성 가능한 산출물을 원본으로 취급하지 않는다.

## 진행 원칙

요청한 모델의 요구를 파악하고 부품 사전과 결합 사례를 검색해 설계한다. 새로 확인한 부품 정보와 재사용 가능한 검증 사례는 공통 자료에 반영한다. 저장된 자료가 늘어나는 것을 모델 자체의 재학습으로 표현하지 않는다. 검증하지 않은 모델을 완성 또는 조립 가능하다고 선언하지 않는다.

이전 스페이스의 작업 기록은 현재 환경에서 확인된 사실과 구분한다. 파일이 전달되지 않은 자료나 과거의 완료 기록을 새 설계의 검증 근거로 사용하지 않는다.

## 수집·설계 순서

고브릭스의 판매 부품 목록을 먼저 확보하고 형상 종류와 색상 변형을 구분한다. 전체 목록 수집과 형상·연결 정보의 정밀화를 구분하며, 모델에 필요한 부품부터 정밀화한다. 이후 필요한 구조의 설명서를 참고해 설계하고 재사용 가능한 결합 사례를 남긴다. 전체 수량과 수집 완료 여부는 출처와 페이지 범위를 확인한 경우에만 확정한다. 뷰어 구현·배포는 보류하고 첫 모델 검토 시점에 진행한다.

가격은 색상별 판매 상품 기준으로 통화·확인 시점·구매 단위를 구분한다. 실제 묶음 가격이 확인된 경우에만 묶음 수량·총액·개당 환산가와 출처를 기록한다. 주문 한도를 묶음 수량으로 해석하거나 수량 할인을 추정하지 않는다. 공개 낱개 단가 합계와 대량 구매 원가를 구분하고, 묶음 조건 조사가 오래 걸리면 미확인으로 남겨 부품 수집을 우선한다.

## 현재 개발·검토 방법

기존 체크아웃을 사용하며 별도 Git worktree를 만들지 않는다. `viewer`에서 `npm ci --ignore-scripts` 후 `npm run build`로 모델과 허용된 형상 자산을 포함한 정적 뷰어를 만든다. 로컬 개발은 같은 디렉터리에서 `npm run dev`로 시작한다. `models`의 MPD와 `assets`가 뷰어 배포물에 포함되며 공개 사이트 방문자는 이를 내려받을 수 있다. 저장소는 비공개로 유지한다. 모델 검증은 저장소 루트에서 `python3 tools/validate_tyrannosaurus.py`, 뷰어 검증은 `viewer`에서 `npx playwright test`로 수행한다. 모델 원본은 MPD 파일에서 직접 관리하며, 일회성 티라노 생성 스크립트와 이전 스페이스 작업 기록은 보관하지 않는다.

## 도구 목록과 재사용 원칙

작업을 시작하기 전에 이 목록과 관련 도구 파일 맨 위의 기능 설명을 확인한다. 아래 명령은 저장소 루트에서 실행한다. `<...>`는 실제 입력 경로로 바꾼다. 설명을 확인하는 목적으로 도구를 무작정 실행하지 않는다.

| 현재 파일 | 용도 | 실행 방법 | 변경 대상 |
| --- | --- | --- | --- |
| `tools/collect_gobricks.py` | 공식 판매 목록·가격 수집 | `python3 tools/collect_gobricks.py --cache <수집 폴더>` | 지정 폴더의 페이지 JSON |
| `tools/build_gobricks_dictionary.py` | 수집 자료 검사·사전 생성 | `python3 tools/build_gobricks_dictionary.py --cache <수집 폴더>` | 부품 사전 전체, 저장 중 임시 파일 |
| `tools/prepare_geometry.py` | 필요한 형상 추출·경로 변환 | `python3 tools/prepare_geometry.py <complete.zip 경로>` | 에셋 형상·색상과 에셋 정책 내부 목록 |
| `tools/enrich_dictionary.py` | 치수·선택된 연결 정보 보강 | `python3 tools/enrich_dictionary.py` | 부품 사전의 형상 관련 정보 |
| `tools/validate_tyrannosaurus.py` | 현재 티라노·에셋 검사 | `python3 tools/validate_tyrannosaurus.py` | 없음; 콘솔 출력만 수행 |

### 실행 순서와 현재 한계

판매 정보가 필요할 때만 수집 → 사전 생성 순서로 실행한다. 사전 생성은 기존 형상 보강 정보를 초기화하므로 단순 가격 갱신 목적으로 무작정 실행하지 않는다. 기존 보강 정보의 보존·복원 방법을 먼저 검토한다.

새 형상이 필요할 때만 형상 추출 → 사전 형상 보강 → 모델 검증 순서로 진행한다. 형상 추출은 코드의 TOP 목록을 기준으로 불필요한 형상을 삭제하므로 다른 모델이 사용하는 형상도 포함하는지 확인한다. 형상 보강은 현재 mapping의 38종과 일부 연결 규칙만 지원한다.

현재 검증 도구는 티라노 경로·160개 수량·부위 목록이 고정되어 있다. 범용 검증기로 취급하거나 다른 모델에 복사하지 않는다. 다른 모델을 지원할 때 기존 도구를 공통화하고 모델별 요구사항은 해당 모델 작업파일에 둔다. 격자 검사를 정밀 간섭·실물 조립 검증으로 표현하지 않는다.

### 유지 관리 규칙

- 기존 도구를 먼저 검색하고 기능·입출력·부작용을 읽은 후 재사용한다. 같은 기능의 도구를 매번 새로 만들지 않는다.
- 기능이 부족하면 기존 도구를 개선한다. 새 도구가 필요할 때는 기존 도구로 처리할 수 없는 이유와 파일명·목적을 먼저 보고한다.
- 파일명은 동작과 대상을 드러내도록 짓는다. 모델별 검증 스크립트를 늘리지 않는다. 파일을 나누거나 합치는 기준은 기능과 재사용성이다.
- 모든 도구 파일의 맨 위에 기능·입력·출력·실행 예시·주의사항·검증 한계를 한국어로 설명한다.
- 도구의 이름·기능·명령·출력 경로가 바뀌면 이 표와 해당 파일 상단 설명, 호출하는 코드도 함께 갱신한다.
- 캐시·임시 파일·형상·빌드 결과를 만드는 경우에도 생성 범위를 실행 전에 보고한다. 사용자가 승인한 새 모델 작업파일만 기존 예외를 적용한다.
- 도움말 지원 여부를 확인한다. 현재 수집·사전 생성·형상 추출은 `--help`를 지원하지만, 형상 보강·티라노 검증은 지원하지 않는다.
