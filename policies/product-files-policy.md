# 제품별 핵심 원본 관리 정책

최종 갱신: 2026-11-03

제품별 위치는 `work/products/<english-product-slug>/`로 통일한다. 최종 핵심 원본은 세 파일이지만 작성 시점을 구분한다.

## 초안 설계·3D 검토·수정 반복

- `project.md`: 사용자 요청과 확정 요구, 설계 판단·근거, 미해결 사항, 진행 상태·완료 근거·다음 행동을 함께 기록한다. 며칠에 걸친 작업도 복구 가능하게 갱신한다. 몸통을 닫기 전에 끼워야 하는 부품, 접근 불가, 서브모듈 선후조건처럼 모델 성립에 필수인 조립 제약은 즉시 기록해 설계에 반영한다.

- `model.mpd`: 실제 3D 부품 위치·방향과 두개골·척추·다리 등의 서브모델을 기록하고 항상 최신 상태로 유지한다. 공통 부품 형상은 `work/parts-library`를 참조한다. 수량은 필요할 때 모델에서 계산한다.

이 단계에서는 위 두 원본을 유지한다. 중간 수정마다 상세 조립 단계·최종 부품표·설명서 PDF를 새로 작성하거나 갱신하지 않는다. 검토에 필요한 3D 미리보기는 파생 산출물로 허용한다.

## 최종안 확정 후 조립설명서 제작

사용자가 최종안을 확정하고 ‘이걸로 조립설명서를 만들어보자’고 지시하면 `assembly.json`을 생성·정리한다. 이 파일에 최종 부품 구성(형상·색상·수량/BOM), 조립 단계·선행조건, 서브조립 연결 방향과 순서 교환 가능한 구간을 기록한다. BOM은 모델에서 산출하며 별도 수작업 중복 목록으로 어긋나지 않게 한다. 부품 ID·색상·수량·서브모델 참조·최종 배치 및 조립 단계가 모델과 일치하는지 검증하고 접근 불가·선후관계 모순을 검토한다. 설명서 PDF·렌더는 이 원본에서 생성한다.

세 파일은 최종 핵심 원본 기준이며 모든 의존성·파생 산출물까지 세 파일로 제한한다는 뜻은 아니다. 새 공룡 작업은 공통 정책 → 해당 `project.md` → `model.mpd` → 최종 설명서 단계에 존재하는 `assembly.json` 순으로 읽는다. 파일이 없으면 실제 작업 단계에 맞춰 필요한 원본만 생성하며 빈 모델·빈 조립 데이터나 가짜 완료 상태를 만들지 않는다. 설계·도구 조작·검증과 기록 갱신은 어시스턴트가 수행한다.
