# BRICK 통합 정책

## 현재 저장·문서 관리 원칙

사용자의 최신 요청에 따라 GitHub의 이 저장소를 이전 대상이자 작업 저장소로 사용한다. 아래 이전 정책 중 BRICK Space를 기준 원본으로 삼거나 Space에 다시 저장하라는 규칙은 이 결정으로 대체한다. Space는 아직 삭제하지 않았으며 전체 자료 이전도 완료되지 않았다.

문서는 `.docs`의 세 파일로 관리한다. 정책은 `policy.md`, 조사·설계 참고는 `references.md`, 이전 범위와 누락·재개 안내는 `migration.md`에 통합한다. 문서를 추가하기 전에 기존 파일에 합칠 수 있는지 먼저 확인하고 꼭 필요한 경우에만 추가한다. 실제 모델·부품 라이브러리·도구·작업 상태 같은 실행 데이터는 문서 수 제한 때문에 합치거나 삭제하지 않는다.

현재 작업 상태는 `../work/task-state.json`에 보존한다. 이 상태 파일의 완료 기록은 이전 환경의 기록이며 현재 저장소에서 검증된 결과가 아니다. 설계를 재개하기 전에 `migration.md`의 누락 현황을 확인한다. 아래 기존 정책의 옛 문서 경로는 이 통합 문서를 가리키는 것으로 해석한다. 원본 문구는 이전 커밋에 보존되어 있다.


## 프로젝트·설계 정책

클라우드 실행 환경의 작업 파일은 Space 원본 복구·설계 실행·검증에 필요한 범위에서 허용한다. 실제 결과·정책·작업상태·원본 모델은 BRICK Space에 저장하고 다시 읽어 확인한다. Mac 경로·localhost 링크에 의존하지 않는다. 이전 담당의 전체 manifest와 완료 receipt를 확인하기 전에는 이전 완료나 필수 원본 복구 완료를 선언하지 않으며, 해당 담당이 관리 중인 첨부 manifest·receipt를 동시 수정하지 않는다.

#### Cloud execution and Space storage

BRICK은 사용자 PC 없이 작업을 이어갈 수 있도록 Space에 원본을 보관하고 클라우드 Codex에서 설계·검사를 실행하는 방식을 기본으로 한다. Space는 보관 장소이며 계산용 파일시스템을 대신하지 않는다. 클라우드 Codex의 실제 환경 설정과 Space 읽기·저장 연결은 별도로 검증하며, 정책 저장만으로 환경 전환 완료를 선언하지 않는다.

- Space의 최상위 그룹은 policies, tests, work 세 개로 유지한다. 폴더명과 문서·파일명은 영어로 작성한다. tests/temp는 일회성 자료, tests/tools는 반복 사용하는 도구와 자료를 둔다.

- 재개 시 최신 네이티브 정책, 제품 작업 문서, 작업 상태, 원본 모델을 읽는다. 클라우드 작업 환경의 Space 접근과 실행 도구를 확인하고 마지막 검증된 체크포인트에서 이어간다. 이전 ChatGPT Work Cloud 작업과 클라우드 Codex는 서로 다른 실행 환경으로 취급하며 파일·도구·로그인이 자동 전달된다고 가정하지 않는다.

- 클라우드 작업 환경에서 부품 라이브러리와 도구를 재사용한다. 환경이 유지되고 해시가 일치하면 매번 전체 자료를 내려받거나 재설치하지 않는다. 새 환경이나 누락·불일치가 있을 때만 필요한 범위를 복구·검증한다. 변경된 원본·재사용 도구·결과·작업 상태를 Space에 반영한다.

- 안전한 작업 경계에서 모델과 재개 자료를 함께 저장하고 재읽어 확인한다. 체크포인트에 모델 해시, 변경 내용, 검증 결과와 한계, 미완료 사항, 다음 행동을 남긴다. 클라우드 임시 디스크만을 영구 원본으로 사용하지 않는다.

- 결과 확인에 로컬 Codex나 사용자 PC의 서버 실행을 요구하지 않는다. 3D 미리보기는 Space 또는 접근 가능한 클라우드 주소로 제공하고 다른 PC에서도 열 수 있게 한다. 원본 모델과 미리보기의 버전 일치를 확인하며 실제 브라우저 확인 여부를 구분한다.

- 로컬 설계·생성·조사와 전체 원본 복구를 기본 경로로 사용하지 않는다. 부득이한 전송·검증 임시 사용만 최소화하고 사용 후 정리한다. 클라우드 접근이나 실행이 막히면 오류와 마지막 저장 상태를 기록하고, 로컬로 임의 전환하지 않는다.

- 초안·반복 수정 단계에는 project.md와 model.mpd를 유지한다. 상세 assembly.json, 최종 부품표와 PDF는 사용자가 최종안을 확정하고 조립설명서 제작을 지시할 때 정리한다.

### 스페이스 프릭 정책

최종 갱신: 2026-11-03

#### 기록 원칙

사용자가 확정한 프로젝트 방향과 결정 사항만 기록한다.

#### 프로젝트

- 레고 브릭을 활용한 독자적인 창작물 설계도를 만든다.

- 작품을 주제별 시리즈로 전개한다.

- 현재는 라이선스 취득 없이 제작·판매할 수 있는 창작물을 중심으로 한다.

#### 첫 번째 시리즈

- 시리즈명은 **Brick Fossils**로 한다. 공룡 골격·화석 형태의 모델을 전개한다.

- 고브릭스 부품을 활용해 공룡 골격·화석 형태의 독자적인 모델 설계도를 만든다.

- 부품 자료의 수집·저장·재사용은 부품 라이브러리 정책(이 문서의 해당 절)을 따른다.

#### 후속 시리즈 선정 기준

- 소재 자체에 흥미와 팬층이 있고, 어린이의 장난감 또는 성인의 피규어로 소장하고 싶은 매력이 있어야 한다.

- 조립하는 재미와 완성 후 전시하는 매력을 갖춘다.

- 작품을 계속 추가할 수 있고, 여러 개를 함께 진열했을 때 수집 욕구와 시각적 매력이 커지는 컬렉션을 지향한다.

- 공룡 골격 시리즈와 다른 매력을 갖춘다.

- 동서양 구분 없이 매력적인 소재를 찾는다.

- 기존 레고 시리즈와 차별화되는 주제를 지향한다.

후속 시리즈의 구체적인 주제는 아직 미정이다.

#### 작업 폴더 관리

- BRICK 아래의 작업 자료는 policies, tests, work 세 폴더로 관리한다.

- policies에는 확정된 정책 문서를, work에는 실제 작업 결과와 필요한 참고자료를 저장한다.

- 테스트 관련 파일은 tests 안에서 용도에 따라 나눈다.

- tests/temp에는 일회성 실험 파일과 임시 산출물을 저장하고, 사용이 끝나면 삭제한다. 이 하위 폴더는 통째로 삭제해도 재사용 자료나 실제 작업 결과에 영향이 없도록 한다.

- tests/tools에는 반복해서 사용하는 검사 도구, 테스트 스크립트, 테스트 이미지 및 필요한 재사용 자료를 보존한다. 필요하면 그 안에서도 영어 이름의 하위 폴더로 정리한다.

- tests 전체를 임시 폴더로 취급하지 않는다. 정리는 파일의 재사용 필요성을 기준으로 한다.

- 폴더명과 파일명은 영어로 작성한다. 문서 본문은 사용자가 요청한 언어를 따른다.

- 필요한 파일만 유지하고 완료된 일회성 임시 기록과 산출물은 정리한다. 반복 검사나 후속 작업에 필요한 자료는 유지한다.

#### 작업 중 대화와 실행 주체

- 사용자의 질문·의문·토론은 상황 설명 요청일 수 있으므로 그 자체를 수정·중단·취소 지시로 간주하지 않는다. 발언의 전체 문맥을 듣고 설명하며, 명시적인 실행·금지·방향 변경 지시를 반영한다.

- 이미 승인된 작업은 질문 때문에 임의로 중단하지 않는다. 대화 후에도 같은 작업을 계속하며, 명시적인 중단 요청·필수 승인·안전 규칙·실제 도구 장애는 따른다.

- 설계, 부품 선택·배치, 도구 선택 및 기술 검증은 어시스턴트가 수행한다. 사용자에게 도구 조작이나 반복 실행·검증을 떠넘기지 않는다. 사용자용 조작 UI 대신 실제 설계에 필요한 최소 내부 도구를 유지한다.

#### 구조 판단과 완료 기준

- 실물 결합강도 시험을 필수 후속 과제나 완료 대기·진행 차단 조건으로 두지 않으며 사용자에게 요구하지 않는다.

- 어시스턴트가 공식 설명서의 지지 구조, 힘 경로, 모멘트와 무게중심, 저장 형상 및 물리 원리를 참고해 구조를 판단하고 불확실한 부분은 보수적으로 보강한다. 해석 범위는 필요할 때 ‘설명서·형상·물리 원리에 따른 추정’으로 표시한다.

- 실제 측정하지 않은 결합강도나 공차를 검증된 사실 또는 보편적인 확정 수치로 만들지 않는다. 미측정 사실은 해석 범위로 남기며 필수 할 일로 전환하지 않는다.

- 구조 판단은 공식 설명서의 실제 조립 구조를 기준 사례로 삼아 수치와 근거를 기록·비교한다. 부품 질량의 출처/추정 구분, 실제 맞물린 연결점 수, 연결 형태·방향, 지지점에서 무게중심까지 거리, 힘 경로·모멘트, 보강 유무를 실제 설계에 필요한 만큼 남긴다.

- 비슷한 하중·자세의 기준 사례와 상대 비교해 보수적으로 판단한다. 후속 설계에서 로컬 근거 기록을 재사용·수정해 판단을 개선하며, 기록 없는 자동학습을 전제로 하지 않는다. 단순 돌기 개수에 정비례하는 강도나 실측 없는 확정 뉴턴값을 만들지 않는다.

- 같은 연결점 수라도 작은 1점 부품 두 개보다 2점을 가진 하나의 연속 부품이 더 단단하게 느껴지고 이음새가 약점이 될 수 있다는 사용자 경험을 검토 가설로 남긴다. 실측 확정 법칙이나 강도 배수로 사용하지 않는다. 구조 비교에는 연결을 공유하는 연속 부품, 이음새 위치·방향, 위아래 층의 이음새 엇갈림, 긴 부품으로 가로질러 묶는 보강, 힘 경로 및 비틀림·벗겨짐 가능성을 포함한다.

- 헐거움·뻑뻑함 편차를 고려해 보수적으로 설계한다. 평균값·편차의 근거가 없으면 임의 평균·안전계수·확정 허용하중을 만들지 않는다. 연결 강도는 근거와 불확실성을 밝힌 범위·민감도 가정으로 표시하고, 약한 결합 조건과 보강 대안을 비교한다.

- 긴 부품의 장점은 결속 방향에 따라 달라진다. 같은 브릭을 일렬로 쌓아 좌우로 묶지 않은 구조의 흔들림·미끄러짐·분리 가능성과, 이음새 엇갈림·가로지르는 결속의 효과를 함께 비교하며 ‘긴 브릭이 항상 강하다’는 법칙으로 사용하지 않는다.

#### 제품별 원본 관리

- 제품별 원본은 [제품 파일 정책](product-files-policy.md)을 따른다. 초안·검토·수정 단계에는 `project.md`와 `model.mpd`를 최신 유지하고 필수 조립 제약을 `project.md`에 기록한다. 사용자가 최종안을 확정하고 조립설명서 제작을 지시하면 상세 `assembly.json`을 생성·정리해 최종 세 원본을 갖춘다. 중간 수정마다 상세 단계·최종 부품표·PDF를 작성하지 않으며 검토용 3D 미리보기는 허용한다.

#### 형태가 중요한 모델의 설계 순서

- 부품 배치에 앞서 공신력 있는 실물·복원 자료와 공식 조립 사례를 직접 확인하고, 전체 크기·비례·해부학적 랜드마크·빈 공간·테이퍼를 제품 project.md에 정한다. 연결 그래프 통과만으로 형태 품질을 판정하지 않는다.

- 형태 검토 → 내부 힘 경로와 자립/지지 조건 → 실제 부품 연결과 필요한 관절 → 저장 모델의 시각·연결·간섭 검토 순으로 반복한다. 골격은 몸통 판/막대에 장식을 붙인 상태를 완료로 삼지 않는다.

- 사용자 불합격 버전은 현재 미리보기로 계속 제시하지 않는다. 변경 이유와 새 검토 게이트를 제품 원본에 남기고, 재개할 때 정책 → 제품 project.md → 작업 상태 → model.mpd 순으로 읽어 마지막 미완료 게이트부터 계속한다.

#### Cloud recovery and model review

Space 원본 재개 시 manifest·조각·원본 목록·세 압축파일·전체 파일 해시를 클라우드에서 독립 검증하고 복구 receipt를 Space에 저장·재읽는다. 이전 아카이브의 정책·상태는 스냅샷이며 최신 네이티브 정책/작업상태를 덮어쓰지 않는다. 복구 성공·모델 실행 성공·형태 합격·구조 추정 합격·3D 화면 검증은 각각 기록한다.

검토에는 저장 MPD의 해시와 재읽은 배치수를 사용한다. 동일 형상·좌표·행렬의 중복 배치, 선언 연결 그래프와 고립 부품, 접속점 중복 점유, 실제 최저점/발 지면 접촉을 확인한다. 연결 기록 누락과 실제 미결속은 구분하고, 표면 교차 후보를 확정 간섭이나 무충돌 증명으로 바꾸지 않는다. 공면·완전포함·접속점 주변 제외 등 검사 한계를 결과 옆에 남긴다.

Space 3D 용량 제한은 원본과 별개인 표시 데이터의 인덱스화·압축·동일 형상 재사용으로 줄일 수 있다. 압축 전후 배치/실제 좌표 오차를 계산하고 MPD의 실제 부품 형상·회전을 임의 변형하지 않는다. HTML 저장·구문/모의환경 검사만으로 실제 GPU·브라우저 렌더가 검증됐다고 하지 않는다. 사용자 PC나 localhost로 우회하지 않는다.

#### Long running checkpoints

장기 설계는 안전한 생성·검사 경계에서 실제 모델·생성기·재개 데이터·같은 MPD 해시의 검토 결과를 Space에 저장하고 재읽어 확인한다. 변경 부위·배치수·치수·확인 범위·미통과 게이트·다음 행동을 구분한다. 체크포인트는 완료·중단·재승인 대기가 아니며 승인된 실행을 이어간다. Space3D 좌표가 최신 MPD보다 앞선 버전이면 그 차이를 명시하고 동일 배치로 갱신한다.

### 제품별 핵심 원본 관리 정책

#### 초안 설계·3D 검토·수정 반복

#### 최종안 확정 후 조립설명서 제작

사용자가 최종안을 확정하고 ‘이걸로 조립설명서를 만들어보자’고 지시하면 `assembly.json`을 생성·정리한다. 이 파일에 최종 부품 구성(형상·색상·수량/BOM), 조립 단계·선행조건, 서브조립 연결 방향과 순서 교환 가능한 구간을 기록한다. BOM은 모델에서 산출하며 별도 수작업 중복 목록으로 어긋나지 않게 한다. 부품 ID·색상·수량·서브모델 참조·최종 배치 및 조립 단계가 모델과 일치하는지 검증하고 접근 불가·선후관계 모순을 검토한다. 설명서 PDF·렌더는 이 원본에서 생성한다.

세 파일은 최종 핵심 원본 기준이며 모든 의존성·파생 산출물까지 세 파일로 제한한다는 뜻은 아니다. 새 공룡 작업은 공통 정책 → 해당 `project.md` → `model.mpd` → 최종 설명서 단계에 존재하는 `assembly.json` 순으로 읽는다. 파일이 없으면 실제 작업 단계에 맞춰 필요한 원본만 생성하며 빈 모델·빈 조립 데이터나 가짜 완료 상태를 만들지 않는다. 설계·도구 조작·검증과 기록 갱신은 어시스턴트가 수행한다.

#### 목적과 시작 절차

아래 수집·조회·배치·검증 절차는 어시스턴트가 수행하는 내부 작업이다. 사용자가 직접 명령을 실행하거나 기술 검증을 할 것을 전제로 하지 않는다.

과거 대화 없이 저장 자료만 읽어 공룡 골격 시리즈의 부품을 검색·선택·배치할 수 있게 한다. 판매자 번호만 저장한 항목은 설계용 완료 자료로 취급하지 않는다.

새 세션은 이 정책과 `policies/project-policy.md`를 먼저 읽고, `work/task-state.json`, `work/parts-library/README.md`, `verification.json`, `catalog.json`, `purchasing.json`, `ldraw/manifest.json` 순으로 기존 범위와 제한을 확인한다. 아래 명령은 BRICK 루트에서 실행한다. 추가 배치 200개는 요청된 번호를 기존 `catalog.json`의 `id` 및 구매 자료의 `ldraw_id`와 대조하고 중복을 제외한다. 요청 목록·진행·누락·다음 행동은 기존 `work/task-state.json` 하나에서 관리한다.

#### 저장 위치와 최소 산출물

- 루트는 `policies`, `tests`, `work`만 사용한다. 파일명·폴더명은 영어로 한다.

- 실제 데이터는 `work/parts-library`에 둔다. `catalog.json`은 형상·연결 검색의 기준, `purchasing.json`은 브랜드 대응 및 판매 근거의 기준이다.

- `ldraw/parts`, `ldraw/p`에 원본과 재귀 의존성을 원래 상대경로로 보존한다. 파일별 URL·저자·라이선스·SHA-256은 `ldraw/manifest.json`, 라이선스 원문은 `ldraw/CAreadme.txt`에 보존한다.

- 형상에서 생성한 최소 식별 이미지는 `images/<id>.svg`로 보존한다. 사진만으로 치수나 연결을 확정하지 않는다. 이미지는 기계 판독 연결 정보나 3D 원본을 대체하지 않는다.

- 연결 배치는 `sample-scene.json`과 `sample-scene.ldr`, 검증 결과는 `verification.json`에 저장한다. 설명은 README 하나에 간결히 모은다.

#### 부품 필수 필드와 좌표

`catalog.json`의 `schema_version`, `units`, `frame`, `compatibility`를 유지한다. 부품별 필수 필드는 `id`, `name`, `gobricks_ref`, `tags`, `ldraw_file`, `image`, `bounds_ldu`, `size_mm`, `connectors`, `internal_supports`, `through_holes`, `through_holes_scope`, `connection_inventory_scope`, `geometry_status`다. `id`는 LDraw 파일의 실제 형태 식별자로 관리하고 별칭/변종은 판매 자료에서 명시한다. 기존 60470처럼 이동 파일을 사용하면 최종 참조 형태까지 따라가 확인한다.

길이는 LDU, 1 LDU=0.4mm, 돌기 간격 20 LDU, 플레이트 높이 8, 브릭 높이 24다. 오른손 좌표계이고 위쪽은 -Y다. 원점은 원본 LDraw 기준이며 부품마다 다르므로 임의로 중심 이동하지 않는다. `bounds_ldu`는 모든 하위 형상을 변환한 전체 외접상자이며 돌기와 돌출 조인트도 포함한다. 몸체 높이와 전체 크기를 혼동하지 않는다. 행 우선 3×3 행렬로 `world = matrix × local + translation`을 사용한다.

연결점은 고유 `id`, `kind`, `position`, 단위 `axis`, `evidence`를 갖는다. 돌기는 몸체 위 돌기 시작면, 하부 수용점은 바닥 착좌면, 볼·소켓·클립은 중심, 바는 축 구간의 중점이다. 돌기와 수용점의 착좌면은 일치하고 돌기는 수용 공동 안으로 들어간다. 돌기·튜브·핀·구멍·클립·바·볼·소켓의 위치와 방향을 해당 부품에 존재하는 만큼 기록한다. 내부 지지 튜브를 개별 돌기 수용 구멍으로 오인하지 않는다. 열린 돌기의 관통 구간과 몸체 전체 관통을 구분한다.

`stud`, `underside_stud_receiver`, `bar`, `clip`, `ball8`, `socket8`은 현재 구현된 종류다. 다른 연결은 기존 종류로 억지 분류하지 말고 새 종류의 치수·호환 규칙·검증 절차를 명시한다. 바에는 반경과 끝점 구간, 클립에는 축·끼움 반경 및 탄성 간섭 여부, 볼에는 반경, 소켓에는 대응 볼 규격을 기록한다. 연결 상대 종류와 샘플 부품을 재조회할 수 있어야 한다. 고정/회전/구면/미끄럼 가능성을 구분한다. 운동 한계를 모르면 `null` 및 이유를 기록하고 임의 각도를 넣지 않는다. 원본 작성자의 운동 주석은 출처와 조건을 함께 기록하며 브랜드 실측 범위로 승격하지 않는다.

#### 근거와 누락 처리

연결점 근거는 원본 파일/변환식으로 확인한 기하, 격자에서 도출한 의미 정보, 판매자 대응 표기, 추정, 실물 검증을 구분한다. `evidence`, `geometry_status`, `fit_status`, `motion.status` 등에 해당 범위를 명시한다. 실물 미측정을 기하 검증으로 대체하지 않는다. 재질·공차·마찰·탄성·하중 능력은 실측 없이 확정하지 않는다. 실물 결합강도 시험은 필수 후속 작업이나 완료·진행 조건으로 두지 않고 사용자에게 요구하지 않는다. 구조 판단은 어시스턴트가 공식 설명서의 지지 구조, 힘 경로, 모멘트·무게중심과 저장 형상을 참고해 수행하며 필요하면 보수적으로 보강한다. 해석은 설명서·형상·물리 원리에 따른 추정으로 표시하고 보편적인 결합강도 수치를 만들지 않는다.

판매 자료는 URL, `checked_at`(한국 날짜), 고브릭스 번호, 대응 LDraw 번호, 확인한 색상 코드/SKU, 재고 상태, 브랜드 형상 검증 범위를 포함한다. 색상명을 확인하지 못하면 `null`로 두고 숫자 코드의 체계를 혼동하지 않는다. 상품 변종 목록과 가격이 있어도 재고가 있다는 뜻은 아니다. 재고 미확인은 `unknown`, 판매 불가 표시는 그 사실과 확인 범위를 기록한다. 구매 직전에는 별도 재확인이 필요하다. 자동 구매·문의 발송은 하지 않는다.

원본과 모든 재귀 의존성의 라이선스를 확인한다. 출처·저자·라이선스가 불명확한 파일은 재배포 완료 상태로 두지 않는다. 서버가 403을 반환하면 우회하지 않는다. 허용된 공개 미러를 사용하면 미러 URL과 원본의 성격, 파일 해시를 기록한다. 메타데이터·연결 주석은 자체 작성, LDraw 형상과 그 파생 이미지는 원본 저작자와 라이선스에 연결한다.

누락 자료는 삭제하거나 수치로 메우지 말고 명시한다. 형상 누락은 설계 사용 불가, 연결 미확정은 해당 연결 자동 배치 불가, 구매 근거 누락은 구매 준비 미완료다. 기하학적 선택 가능 여부와 구매 가능 여부는 별개다.

#### 실제 도구와 다음 배치 절차

1. 현재 결과를 재검사한다: `python3 tests/tools/verify_parts_library.py`. 실패하면 원인과 현재 제한을 상태 파일에 기록하고 완료로 표시하지 않는다.

2. `python3 tests/tools/parts_library.py query neck_joint` 또는 `query clip`, `query 3001`로 저장 자료를 조회한다. 검색은 로컬 JSON에서 실행하며 네트워크가 필요 없다.

3. 추가할 번호를 명시하여 수집한다: `python3 tests/tools/build_parts_library.py --parts 3004:Brick`. 쉼표로 `번호:판매처카테고리`를 나열할 수 있다. 이 명령은 지정 부품의 판매 자료와 LDraw 의존성을 수집하고 기존 다른 부품·manifest를 보존한다. 네트워크와 판매처 페이지 구조에 의존하므로 실패·누락을 반드시 확인한다. 옵션 없는 실행은 기존 8개 시범 부품을 대상으로 한다. 기본 8개 외의 새 배치는 반드시 명시적 `--parts`를 쓴다.

4. `python3 tests/tools/parts_library.py inspect <id>`로 저장 형상을 재귀 해석해 외접상자와 원본 프리미티브 변환을 확인한다. `walk`, `svg`, `dump` 함수를 재사용해 형상을 읽고 식별 이미지를 저장한다. 임시 출력은 `tests/temp`에 둔다.

5. 자동 추출 결과를 검토한 뒤 위 필드의 부품 레코드를 `catalog.json`에 추가한다. **수집기는 연결 주석을 자동 완성하지 않는다.** 하부 격자·클립 중심·관통 여부·호환성·운동 범위는 원본 형상과 근거를 검토해 직접 작성한다. `parts_library.py build`는 기존 시범 8개 주석을 다시 생성하는 명령이며 추가 부품의 주석 생성기가 아니다. 기존 추가 레코드는 보존한다.

6. 갱신 시 같은 `id`는 한 레코드로 교체하고 중복을 만들지 않는다. 원본 해시가 달라지면 해당 연결 주석·이미지·샘플을 재검사한다. 같은 형상이 다른 판매 번호로 제공되면 형상 복제 대신 판매 대응을 추가한다. 이전 검증 날짜를 새 검증처럼 재사용하지 않는다.

7. 새 연결 종류마다 최소 한 쌍을 로컬 자료에서 선택해 배치한다. 기존 `verify_parts_library.py`의 저장 자료 조회→태그/종류 선택→좌표/축 검사→LDraw 장면 생성 패턴을 확장한다. 같은 좌표계로 외접상자를 재계산하고 원본 해시·의존성·라이선스를 검사한다. 의도적으로 어긋난 배치를 거부하는 음성 대조도 유지한다. 샘플 연결 성공을 모든 부품의 조립·충돌 검증으로 확대하지 않는다.

8. 검증 결과와 상태 파일의 수집/주석/검증/미해결 수량을 저장한다. 다음 세션은 그 파일과 이 정책만으로 계속할 수 있어야 한다. 200개를 한 번에 완료 선언하지 말고 실제 확보·주석·검증 범위별로 보고한다.

#### 설계 시 구조 판단 근거

실제 모델 설계 때 필요한 만큼 기존 작업 근거 기록에 부품 질량(출처값/추정값 구분), 실제 맞물린 연결점 수, 연결 형태·방향, 지지점에서 무게중심까지 거리, 힘 경로·모멘트, 보강 유무를 수치와 함께 남긴다. 단위·가정·출처 및 불확실성을 명시하고, 공식 설명서의 실제 조립 구조 중 비슷한 하중·자세의 기준 사례와 상대 비교해 보수적으로 판단한다. 단순 돌기 수에 정비례하는 강도나 실측 없는 확정 뉴턴값은 사용하지 않는다. 후속 설계에서는 로컬 근거 기록을 재사용·수정해 판단을 개선한다. 이는 기록으로 재현하는 개선이며 기록 없는 자동학습을 뜻하지 않는다. 현재 부품 수집 단계에서 전체 모델의 하중 기록을 미리 작성할 필요는 없다.

같은 맞물림 수에서도 작은 1점 부품 두 개보다 2점의 연속 부품 하나가 더 단단하게 느껴지고 분할 이음새가 약점이 될 수 있다는 사용자 경험은 **검토 가설**로 기록한다. 이를 실측 법칙이나 ‘2점은 1점의 2배 이상’ 같은 계수로 환산하지 않는다. 비교 기록에는 연결을 공유하는 연속 부품, 이음새 위치·방향, 위아래 층의 이음새 엇갈림, 긴 부품으로 가로질러 묶는 보강, 힘 경로, 비틀림·벗겨짐 가능성을 포함한다.

헐거움·뻑뻑함의 편차를 고려해 평균적인 결합보다 약한 조건에서도 성립하도록 보수적으로 판단한다. 평균값과 알려진 편차의 근거가 없으면 임의 평균·안전계수·확정 허용하중을 만들지 않는다. 연결 강도는 근거를 명시한 범위·민감도 가정으로 다루고, 수치 범위의 근거도 없으면 정성적 약함/강함 조건으로 표시한다. 약한 결합 조건에서의 힘 경로와 보강 대안을 비교하며 가정은 측정값과 구분한다.

#### 완료 판정

실제 파일 저장과 재읽기, 모든 의존성의 로컬 해석, 해시·라이선스 확인, 치수 재계산, 연결 샘플 재구성까지 성공한 범위만 기하 자료 검증 완료다. 샘플 기준을 확장해 새 부품도 검사해야 한다. 재고·브랜드 공차·물리 조립·하중·충돌·전체 운동 범위 중 확인하지 않은 범위는 미확인 사실로 남긴다. 실물 시험 미실시는 완료 대기나 필수 후속 과제를 뜻하지 않는다.

#### 지원 부품 두 개의 일반 배치·검사

시범 장면 재생과 별개로 `tests/tools/place_parts.py`를 사용한다. `query <id>`에서 `connectors[].id`를 읽고 `python3 tests/tools/place_parts.py place 3001:stud1 3004:underside_10_0 --name pair-placement`처럼 부품과 연결점을 지정한다. 결과는 `work/parts-library/<name>.json` 및 `.ldr`로 저장한다. 이름이 같으면 해당 결과를 교체한다. `python3 tests/tools/place_parts.py check pair-placement.json`은 저장 장면을 다시 읽어 호환 종류·중심·축을 검사하고 실패 시 종료 코드 1을 반환한다.

A 부품은 원본 좌표에 고정하고 B의 연결축을 회전한 뒤 연결점이 일치하도록 평행이동한다. 지원 범위는 catalog에 선언된 stud/underside_stud_receiver, clip/bar, ball8/socket8다. 돌기와 수용점 축은 반대, 클립과 바 축은 같은 방향으로 맞춘다. 현재 ball8 축은 볼 중심에서 줄기로 향하고 socket8 축은 소켓에서 개구부로 향하므로 같은 방향으로 맞춘다. 연결축 주위의 비틀림 자세는 최단 회전으로 선택하며 전체 형상 충돌을 해결하거나 여러 연결을 동시에 최적화하지 않는다. 한 연결점 정렬 성공은 다른 돌기·주변 부품과의 무간섭, 물리 결합, 하중 지지를 보증하지 않는다. 새 종류의 축 의미가 다르면 이 규칙을 먼저 확장한다.

#### 티라노 실용 배치와 병렬 읽기

확장 배치의 역할별 준비·누락은 `work/parts-library/role-index.json`, 전 부품의 등록 연결점 검사 결과는 `expansion-verification.json`을 읽는다. `python3 tests/tools/annotate_tyrannosaurus_parts.py`는 검토한 현재 배치의 주석을 재생성하며 범용 자동 주석 생성기가 아니다. `python3 tests/tools/verify_tyrannosaurus_parts.py`는 로컬 형상·외접상자·원본 해시·저자·라이선스 및 모든 등록 연결점의 지원 상대를 검사하고 7쌍의 장면을 `expansion-scene.json/.ldr`에 재구성한다. `partial_interfaces`는 선언한 연결점만 사용 가능하며 모든 구멍·하부 형상이 완성됐다는 뜻이 아니다.

현재 내부 배치기는 Technic 핀/원형 구멍, 십자축/십자 구멍, 십자축/원형 구멍, 바/관형 수용부, 4×4 턴테이블 한 쌍, 클릭 힌지 한 쌍을 추가 지원한다. 축/십자 구멍은 가로 키 방향을 90도 대칭 기준으로 검사한다. 긴 바는 관의 중심에 전체 중점을 놓지 않고 끝에서 유효 삽입 구간을 계산한다. 클릭 힌지는 축을 반대로 정렬해 두 몸체가 같은 위치에 겹치는 기본 배치를 피한다. 이는 선언된 연결 프레임·명목 삽입 길이 검사이며 전체 충돌 해결·부하 보증이 아니다. `place`와 `check`의 호출 방식은 기존과 같다.

대안은 같은 역할의 후보와 실제 호환을 구분한다. `alternatives`에 공통 연결 종류, 외접상자 차이, 배치·결속·연결계열 변경 사항을 기록한다. 보완 관계인 볼/소켓·턴테이블 위/아래를 서로 대체품으로 취급하지 않는다. 관절 계열을 바꾸면 양쪽 부품과 주변 지지를 함께 다시 설계한다.

병렬 설계 담당은 공통 부품 자료를 읽고, 라이브러리 담당만 catalog/manifest를 갱신한다. JSON은 `tests/temp`의 완성 임시 파일에서 원자적으로 교체해 중간 JSON을 노출하지 않는다. 형상·의존성과 manifest를 먼저 확보한 뒤 catalog에 등록한다. 초기 8개 생성기를 재실행해도 확장된 호환 규칙과 추가 레코드를 보존한다.

티라노 실용 배치가 끝나면 전체 고브릭스 판매 카탈로그를 향한 확장을 배치별로 계속한다. 판매 카탈로그 색인 → 중복·형상 변종 정리 → 재귀 형상·연결 주석 → 로컬 검증 순서를 유지하며 단순 판매번호 수집을 설계용 완료로 세지 않는다. 다음 배치와 미확인 사항은 기존 `work/task-state.json`에 남긴다.

#### 공식 판매 인덱스와 표준 부품 확장

`catalog-index.json`은 공식 공개 웹페이지에서 사용하는 읽기 전용 `item/filter`의 제품 ID별 목록이다. `collect_gobricks_index.py --max-pages 20`으로 저장된 페이지 다음부터 한 번에 제한된 수만 읽으며, 기본 요청 간 간격을 두고 403 등 접근 오류가 나면 멈춘다. 인증·구매·문의는 하지 않는다. UI의 전체 색상 선택은 grouping 생략, 제품별 선택은 `grouping=product_id`, 재고만 표시 해제는 `hasInventory` 공백이라는 공개 클라이언트 동작을 근거로 한다. 원본 전체 HTML/JS 사본 대신 쿼리·필드·URL·확인 날짜를 인덱스에 보존한다.

제품 ID별 항목 수, 색상 SKU 수, 기하학적으로 중복 제거된 형상 수는 다르다. 하나의 제품에는 여러 원본 형상 별칭이 있을 수 있고 같은 참조 번호를 공유하는 제품도 있으므로 `shared_reference_groups`는 검토 목록이며 자동 병합 근거가 아니다. 페이지 종료만으로 전체 완료를 선언하지 않고 서버 보고 수·관찰한 고유 제품 수·필터 범위·중복/누락 가능성을 함께 기록한다. 인덱스 항목은 형상·연결 준비 완료 수에 포함하지 않는다. 공식 인덱스의 한 대표 색상 재고는 그 SKU의 확인 시점 기록일 뿐 전체 색상·한국 배송 가능성을 뜻하지 않는다.

`annotate_standard_parts.py`는 현재 검토한 타일·원형·측면 돌기·경사·바/클립 24종의 명시적 좌표 규칙만 재생성한다. 범용 자동 주석기가 아니다. `stud10`은 원형 부품의 곡면에 따라 일부가 잘린 돌기이며 완전한 원통 돌기로 설명하지 않는다. 측면 돌기의 깊이·방향, 헤드라이트의 4 LDU 오프셋, 손잡이의 축/자유 길이 차이를 대안 기록에 보존한다. 지원하지 않은 뒷면 홈이나 특수 하부는 연결로 추정하지 않고 `partial_interfaces`로 남긴다. 기존 티라노 배치 주석기는 이 표준 배치 레코드를 덮어쓰지 않는다. 추가 후 기존 `verify_tyrannosaurus_parts.py`가 전체 catalog를 읽어 검사하며, 현재 11쌍 장면을 같은 expansion-scene 파일에 갱신한다.

#### 정형 직사각 부품의 선택적 확장·검사

검토한 직사각 브릭·플레이트·타일은 `annotate_standard_parts.py`의 명시적 `RECTANGULAR` 표에 역할·가로/세로 격자 수·착좌 높이를 기록한다. 원본 전체 외곽이 해당 직사각 치수에 맞고 추출한 돌기 수가 격자 수(타일은 0)와 일치할 때만 규칙을 적용한다. 프리미티브별 돌기 변환과 하부 격자 근거를 보존하며 비정형·구멍·관절 부품에 이 규칙을 억지 적용하지 않는다.

`python3 tests/tools/annotate_standard_parts.py --ids 3623,60479`처럼 해당 명시적 표의 신규 ID만 처리할 수 있다. `verify_tyrannosaurus_parts.py --ids <쉼표로 나눈 이번 배치 ID>`는 기존 성공 기록을 보존하고 지정 부품의 형상·연결점만 검사한다. `previous_part_results_retained`와 `checked_this_run`으로 재사용 결과와 새 검사를 구분한다. 현재 선택 검사 장면은 직사각 부품 3쌍이며 같은 expansion-scene 파일에 저장한다. 코드·기존 원본·연결 정보가 변경됐거나 실패가 있을 때만 해당 범위의 재검사를 확대한다. 인덱스의 수량 차이는 별도 한계로 남기고 개별 부품 등록의 선행조건으로 삼지 않는다.

#### 전체 판매 제품의 형상 자료화와 연결 준비도

`catalog-index.json`은 판매 제품 ID·색상 SKU·원본 참조 별칭의 인덱스다. 공개 카테고리별 조회로 제품 범위 차이를 보완하며, 제품 ID 수가 같아져도 다른 시점/필터/비공개 전체 범위까지 동일하다고 확대하지 않는다.

`sales-geometry.json`은 모든 인덱스 제품을 처리한 등록부다. 제품별 원본 대응·누락 사유, 실제 로컬 형상·의존성·치수·이미지와 인식된 프리미티브 프레임, 연결 준비 상태 및 대표 색상 재고·구매 근거를 기록한다. 실제 설계용 `catalog.json`과 구분한다. 판매 제품 수, 원본 참조 파일 수, 기하 동등성 판정 수, 주요/부분 연결 준비 수는 서로 다른 집계다. 인쇄 번호에서 기본 몸체만 대응한 경우 파생 후보와 body-only 범위를 명시하고 문양을 확보한 것으로 세지 않는다.

대량 자료화는 `build_sales_geometry.py <공개라이브러리ZIP> <출처URL> [--retry-missing]`로 수행한다. NumPy·Pillow가 있는 번들 Python을 사용한다. 두 번째 묶음에서는 기존 형상 확보 제품을 건너뛰고 미확보만 재대조한다. 필요한 원본·재귀 의존성만 저장하고 원본별 저자·라이선스·SHA-256, 묶음 URL·해시를 보존한다. 기존 확보 파일을 덮어쓰지 않아 라이브러리 확보 버전이 섞일 수 있음을 표시한다. 실제 형상을 해석해 좌표와 치수를 만들며, 이름/URL만 있는 항목을 형상 확보로 세지 않는다. 원본 라이선스·의존성을 확인할 수 없거나 참조 번호가 없으면 항목별 누락으로 남기고 다른 정상 항목을 계속 처리한다.

일반 자동 주석은 원본 설명·직사각 외곽·돌기 수·실제 돌기 위치 격자·착좌 높이를 함께 만족하는 브릭/플레이트/타일과, 예상 구멍 수·20 LDU 간격·20 LDU 두께의 마주 보는 구멍 입구를 확인한 직선 빔에만 적용한다. 나머지는 `geometry_ready_unannotated`로 둔다. `recognized_features`의 돌기나 핀 구멍 입구 프레임은 기하 근거일 뿐, 접속 중심·상대 종류·끼움 깊이·키 방향·운동 특성까지 검토한 `connectors`가 아니다.

`verify_sales_geometry.py`는 전 제품 처리 여부, 실제 저장 원본의 해시·저자·라이선스·모든 참조와 순환 없음, 치수/mm 변환, 로컬 PNG 및 준비도 구분을 검사한다. `parts_library.py query GDS-1000`으로 미주석 제품까지 오프라인 재조회하고 실제 형상 경로/프레임을 얻는다. 주요 연결 준비 수는 **선언된 주요 접속**의 위치·방향·지원 상대·정렬 검사 범위이며, 모든 가능한 접속/부품 조합·브랜드 공차·충돌·강도·운동 한계를 완전히 검증했다는 뜻이 아니다. 부분 주석과 형상만 확보한 항목은 별도 집계한다.

형상만 있는 항목을 설계 준비로 승격하려면 실제 형상에서 돌기/튜브/구멍/클립/바/볼/소켓 등의 접속 의미와 기준점·축·짝·명목 삽입 범위·키/정지 조건·운동 특성을 작성하고, 내부 배치기가 해당 종류를 지원하게 한 뒤 정상/어긋난 배치 검사를 수행한다. 모르는 범위는 표시하며 임의 값으로 채우지 않는다. 현재 수량·미완료 규모는 정책에 고정하지 않고 registry/검증/상태 파일에서 읽는다.

#### 원본 기반 접속 계층

LDCad Shadow Library의 라이선스가 확인된 작성 접속 정보는 `shadow-connections.json`에 별도로 보존한다. 원본은 `connectivity-source`에 저자·이력·CC BY-SA 4.0 및 해시와 함께 두며, 파생 접속 JSON도 같은 라이선스를 명시한다. LDraw 형상 라이선스와 혼동하지 않는다. 상속·포함·제거·격자·스케일·미러 규칙을 해석하고, 원본 단면·성별·캡·그룹·키·프레임과 출처를 유지한다. 좌표 반올림 보정은 도구에 제한값과 원래 값을 보존하며 실물 공차로 해석하지 않는다.

접속별 상대와 정상/오류 배치는 `shadow-connection-verification.json`, 표준 기준점·볼 자유 회전·힌지·키 검사는 `shadow-calibration-verification.json`에 저장한다. `sales-geometry.json`의 `source_connection_evidence`와 `connection-coverage.json`으로 조회한다. 기존 `connection_status`/개별 주석과 새 원본 선언 검증 상태를 서로 덮어쓰거나 수량을 더하지 않는다. 새 원본 선언 전부 통과도 모든 물리적 접속의 완전성으로 확대하지 않는다. 접속이 없거나 상대가 검증되지 않은 경우 개별 미완료를 유지한다. 판매 목록 밖의 검증 상대는 `auxiliary_parts`로 구분하며 고브릭스 판매 제품 수나 구매 가능 근거로 세지 않는다.

BrickNet 공개 번들 라벨은 원본·명세·MIT 고지·해시를 `bricknet-source`에 보존하고, `bricknet-connections.json`/검증 파일에서 별도 계층으로 관리한다. 명시된 별칭 행렬만 적용하고 위치·회전·종류/극성·상대 배치를 검사한다. 이 계층은 상세 단면·캡이 없는 의미/프레임 기반이므로 LDCad 프로파일 검증과 동급으로 표시하지 않는다. 세 계층에서 중복을 제거한 사용 가능 형상 수와 계층별 검증 선언 수를 구분하고, `unresolved_shapes`에는 모두 대조한 실제 잔여 항목만 둔다.

#### 특수 결합과 제조사 공개 모델 조사

원본 라벨 부재만으로 미완료 조사를 끝내지 않는다. 정확한 제조사 상세·이미지·권장 상대, 실제 형상의 특징, 작성된 전체 조립 파일의 상대 변환과 명시적인 별칭을 확인한다. 전용 결합은 `special-connections.json`에 자체 부분 주석으로 저장하고 지원 상대·근거·미확인 범위를 유지한다. 일반 등록 프레임은 물리적 접촉점/힌지 중심이 아니며 작성된 자세를 등록하는 좌표임을 표시한다. 정상/오류 배치와 저장 장면 재읽기로 검증한다. 외부 전용 접속이 없는 소품은 `free-object-classifications.json`에 형상 근거와 한계를 기록한다. 라벨 없음만으로 자유 물체를 단정하지 않는다.

제조사 뷰어의 공개 모델은 정확한 URL·해시·실제 형상 해석 결과·구성 파일별 저자/라이선스를 보존한다. 공개 열람 가능성을 포괄적 재배포 허가로 해석하지 않는다. `manufacturer-models`의 내부 연구 스냅샷과 정식 `ldraw` 자료를 구분한다. 라이선스·저자가 확인된 단편만 개별 근거와 함께 회수하며, 의존성이 없는 정식 원본은 `research-geometry`로 구분해 정상 형상 집합을 불완전하게 만들지 않는다. 공개 파일 텍스트 정규화 해시를 원본 서버 바이트 해시로 표시하지 않는다. 비공식 Parts Tracker 형상은 미인증 상태를 유지한다.

제품별 조사에는 확인한 출처와 실제 실패 주소/오류, 확보한 이미지·설명·명목 치수·접속 지식, 아직 필요한 정확한 원본/하위 파일/권리 근거를 연결한다. 판매 설명과 공개 모델이 충돌하면 그 변형의 정확한 형상으로 승격하지 않는다. 소프트/하드 스프링, 로프 길이, 인쇄 몸체, 묶음 제품은 차이를 남긴다. `product_weight`는 공개 클라이언트의 g 표시 근거가 있는 판매자 보고치로 취급하며 대표 SKU 범위·비실측 상태를 명시한다.

이번 조사 범위와 현재 수량은 README·등록부·검증 보고서에서 읽는다. 기존 통과 결과는 유지하고 변경 형상/의존성/접속과 새 조사 기록만 재검사한다. 조사 가능한 공개 근거를 저장한 완료와 실물 금형·권리·치수 자료가 추가로 필요한 항목을 분리한다.

#### 내부 설계 연구와 공유 가능한 형상의 분리

제조사 모델의 저작자/재배포 권리 미확인은 내부 형상 조사 중단 사유로 일괄 처리하지 않는다. 공개 모델을 정상적으로 확보한 경우, 내부 연구 계층에서 실제 모양·명목 크기·원본 축·돌기/구멍/바/클립/볼·수용 구간·전용 상대를 가능한 만큼 인지하고 제품별 한계를 남긴다. 원본 모델과 파생 연구 자료를 외부 게시/재배포하지 않는다. 공유 가능한 `ldraw` 집합으로 승격하려면 해당 원본·하위 파일의 저자/권리와 형상 대응을 별도로 확인한다. 라이선스 상태, 메쉬 해석 가능 상태, 판매 금형 일치 상태, 접속 검증 범위를 각각 기록한다.

`manufacturer-connections.json`은 내부 연구 연결 조회 기준이다. 기하 프리미티브, 삼각형 기반 표면 피팅, 실제 단면 윤곽, 사진/판매 설명을 서로 구분한다. 표면 피팅은 원본 삼각형 번호·축·반경·구간·잔차와 실제 곡면 각도 합을 보존하며 관찰 수를 완성 접속 수로 세지 않는다. 지지 튜브 바깥면/좁은 포스트를 수용 구멍으로 표시하지 않는다. 타일 공동이나 십자/키 형상을 원형 프로파일로 단순화하지 않는다. 회수한 벽의 축 구간은 빈 삽입 공간 증명과 다르다.

단면 샘플은 실제 빈 공간·비원형 단면·막힘/위상 불일치를 구분하고 검사한 평면 밖으로 확대하지 않는다. 원형 입구 하나로 완전한 보어 깊이를 추정하지 않는다. 부정적 결과와 불일치를 보존하며 명목 간섭을 실제 탄성·공차·유지력으로 바꾸지 않는다. 머리/장식·공구·팩 구성물의 전용 결합과 비구조 접촉 역할을 구분한다. 공개 모델의 자체 형상이 거칠거나 판매 설명과 다르면 이를 명시하고 임의 금형 값으로 보충하지 않는다.

정확한 원본 프리미티브 돌기는 제한된 내부 프로파일 배치에 사용할 수 있으나 저장 장면에 모델 파일·루트·SHA-256과 검사 범위를 남긴다. 일반 표면 후보에는 자동 끼움 승인을 하지 않는다. 이미지/불완전 래퍼 항목도 확인 가능한 연결 종류·역할·비교용 대리 참조와 정확히 필요한 도면/하위 파일/상대 정보를 남긴다. 대리 참조는 정확한 제품 모델 또는 drop-in 대응과 구분한다.
